### 3.2 The plan's own proposals

The following rules are proposed by this plan, not decisions already settled by decision 257:

- Accept only a `.png` destination filename; encode PNG regardless of the input/report format.
- Refuse a requested window below 980x640 logical units in strict mode. Those are today's XAML minimums,
  not an independently approved capture minimum (src/NvtFwCombiner.Presentation.Avalonia/MainWindow.axaml:14).
- Without `--theme`, `--language` and `--motion`, capture uses saved preferences. It is then not reproducible
  across machines. Use all three overrides and light/dark for controlled appearance; System follows the machine.
- A capture run persists nothing: no History insertion, preference/recent-work/configuration save,
  queued local-state save or close-flush write. Existing read-only state remains real.
- When a person-required prompt stops input loading, stderr lists every requested input that was not loaded.
  This list is the plan addition in section 6(b), alongside the owner's prompt PNG/exit-1 decision.
- On Windows, refuse a capture destination folder whose final handle path differs from its supplied spelling
  (mapped/subst drive, 8.3 name or junction ancestor). Validate through the local-file port before window creation,
  return 64, and say that the destination folder must be given by its real path.
- One named 300-second capture deadline starts when MainWindow opens, covers required startup, report loading,
  target readiness, layout/frame and draw/save, and ends with 70 plus stderr naming the active phase.
  Host composition before the window opens is outside this deadline.
  Reuse the confirmed close/drain path; test with an injected deadline rather than waiting 300 seconds.

## 4. Ordered implementation slices

Slice 1 precedes every other slice. Slices 2, 3, 4, 5 and the Hex part of 6 then depend only on slice 1;
only the Build Settings part of 6 additionally needs slice 4's accepted input session. Slice 3 is not required for
other targets: they can use current appearance. No shared file has simultaneous writers.
Slice 1 splits the single UiLaunchOptions parse loop into per-slice partial hooks for token consumption, typed request
validation/construction and help entries. The core retains value syntax, strict-mode detection and cross-target checks.
Later slices implement only their own hooks/files; absent hooks leave future options unsupported in strict mode,
with ordinary recoverable handling preserved. This is one parser, not a registry, plugin framework or second parser.
Slice 1 also installs bounded per-slice dispatch hooks in DesktopLaunchCoordinator so later controllers do not require
shared MainWindow or coordinator-core edits. Hooks run before inputs, before navigation/implicit Settings selection,
and after target publication; appearance/export and capture-check guards are installed before their consumers.
Hooks are additive and run in registration order; a failure stops the chain. Interactive publication hooks run
when the target's own readiness stage publishes, while unrelated optional stages may still be pending.
Capture completion defaults to exit 0/no diagnostic; a hook can set the context's completion result for a
real prompt, applied only after successful PNG publication. Protected inputs are collected once by the parser
and passed unchanged to the launch context and capture validation/publication owners.
Existing user commands, preload sequencing and publication leases stay
the authority. Characterization tests cover the split before any parallel writer starts.
Safe concurrent pairs after 1: (2,3), (2,4), (2,5), (2,6-Hex), (3,4), (3,5), (3,6-Hex), (4,5), (4,6-Hex), (5,6-Hex).

## 6. Decisions for the owner

### 6(a). A correct request asks for a screen that is unavailable

Decided: exit 1, no screenshot, with stderr naming the application's state. Empty History and Build Settings
unavailable for the loaded inputs are expected failures of well-formed capture requests; 64 remains a wrong request.
Slices 5 and 6 test these cases without inventing History entries, accepted sessions or enabled commands.
An existing destination PNG stays byte-identical. Ordinary launches remain recoverable and interactive.

### 6(b). Input loading stops at a warning that needs a person

Decided: save the screenshot of the real prompt and exit 1, saying which prompt stopped it. Listing the requested
inputs that were not loaded is this plan's addition. Never confirm the prompt automatically, load blocked later files or obscure it with another target.
Slices 4 and 6 test the real prompt, partial selection, screenshot, exit and diagnostic; slice 1 provides capture
completion and the confirmed-exit path. A saved warning is evidence of incomplete loading, not a successful target.
Capture/store failure preserves existing destination bytes; shutdown does not answer the input prompt.

### 6(c). Capturing the Version section can start a version check

Decided: a capture run that opens the Version section, through `--settings-section version` or through Settings
