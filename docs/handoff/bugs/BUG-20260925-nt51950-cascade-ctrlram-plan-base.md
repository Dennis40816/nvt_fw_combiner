Status: suspected
Severity: P2
Found: 2026-09-25, Claude Code (Opus 5.5, WS-PARITY sub-agent), while running the candidate side of the non-certifying 1.1.12 v0.9.16 comparison, at `feature/1.1.12/v0916-alignment`@`5648d0fd1` (candidate product source `1c37bd718`)
Where: route `route-7-nt51950-15-ctrlram-replace-4-2-ic-39-nt51950-ctrlram-fw1x-cascade-full-flash`; plan `docs/contracts/v0916-parity-certification-v1.json` (`canonicalInputAuthority.ctrlRamBaseRoutes` binds it to `standardMergeMapVariant` `nt51950-standard-merge-512k`); map `nt51950-ctrlram-fw1x-cascade-full-flash` in `profiles/built-in/nt51950-ctrlram-replace-candidate/families/nt51950-ctrlram-replace.json` (`capacityBytes` 262144, unchanged since the plan's commit `1d1d1cfc`); classifier `src/NvtFwCombiner.Application/InputInspection/FirmwareArtifactClassificationResolver.CtrlRam.cs` (AB layouts are tried before Standard)
Observed: with the plan's inputs (case `nt51950-cascade2-geometry-nt51951-auto-prj-599-alias`, resolving to the NT51951 AUTO_PRJ-599 case), the candidate CLI builds the declared precursor (`standard-merge build --profile NT51950`, report `MapId` `nt51950-standard-merge-512k`, 524288 bytes, SHA-256 `ff9ad012454cab3d9d76d7270dfde7b402d23c2d0376ba6776cd1a242144aa32`, equal to the full-base hash in `docs/contracts/v0916-nt51951-c2-diagnostic-v1.json`). `ctrlram-replace preview --profile NT51950 --ic-num cascade --base <that base> --ctrlram replace-ctrlram-normal=... --ctrlram replace-ctrlram-vn=... --ctrlram replace-ctrlram-diff=...` then exits 1 with `input.bank-reference.metadata-unreadable` (b-bank FWConfig marker count 0), `input.bank-reference.invalid` (`MarkerCardinalityMismatch`) and `input.bank-reference.content`: the 512 KiB base is classified as an NT51950 single AB reference. The NT51951 route with the same base succeeds, and its output equals the plan's approved-correction candidate hash `1536d344...4ebd`.
Expected: ADR 0057 and the plan require every one of the 64 routes to execute on the candidate; this route is `supported` in both the plan's policy and the `v1.1.11` policy and has a canonical input binding.
Evidence: harness run in the test area (`parity-1112/run-c1`), row in `docs/handoff/1.1.12/parity/v0916-local-comparison.json`. Hypotheses, not verified: (a) plan binding defect: the precursor yields 512 KiB while the route's map declares 256 KiB, and the alias case itself excludes NT51951's `0x80000` output identity and keeps NT51950's separate `0x40000` capacity, so no executable base may exist for this route from these inputs; (b) product behavior since AB CtrlRAM Replace: a 512 KiB NT51950 base whose first half is a plausible FlashCode is taken as an AB reference before Standard classification (`f89dbaf30` in `v1.1.11` refactored this path; the a-bank plausibility rule predates it). At first recording the v0.9.16 behavior was unknown because the predecessor was not yet built; see the next line.
Evidence (added with the two-sided run): the map's 262144-byte capacity dates from `v0.9.16`; `99766df75` (first released in `v0.10.1`, "preserve 950-family active DiffNF (#188)") changed its topology from `cascade`, minimum 2 chips, to `exact-count` 2 and added the AUTO_PRJ-599 alias as evidence, without changing the capacity. With the approved predecessor build (run `run-bc1`), v0.9.16 builds the identical precursor base (`ff9ad012...aa32`) and then also blocks the CtrlRAM preview: `profile.v2.compile.map-selection-invalid` ("must identify a canonical image map for the requested runtime reference-replace capacity and topology"). Both versions therefore reject this plan-bound 512 KiB base, which supports hypothesis (a), a plan or alias binding defect, and makes a 1.x regression unlikely; the two versions only word the rejection differently.
