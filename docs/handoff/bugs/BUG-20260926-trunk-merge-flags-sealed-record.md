# BUG-20260926-trunk-merge-flags-sealed-record: merging the trunk into wave 2 makes every descendant fail the structure gate

Status: worked around on 2026-09-26 (wave 2 and its feature branches rebuilt by rebase with identical trees); the root fix is WS-GOV
Severity: P1 (the required `policy / polytail` check fails for `feature/1.1.13/wave2` and every branch built on it, and would fail on `1.1.x` if wave 2 merged as it is)
Found: 2026-09-26, Claude Code (Opus 5.5), while verifying the WS-GOV design commit, at `feature/1.1.13/ws-gov`@`c2b9c1468` (wave 2 `8682dd269` plus documents under `docs/handoff/` only)
Where: merge `beb32b930` ("Merge 1.1.x (wave 1, #457) into the 1.1.13 wave 2 branch"); `scripts/validate_repository.py` `_record_changed_in_commits_after` and `_is_tree_transparent_containment_merge` (ADR 0061).
Observed: `python scripts/verify.py --structure-only` ends `structure=FAIL` (268 s) with one error: `final-complete capability-reuse record changed in commit history: docs/governance/change-records/CLI-REPORT-BUNDLE-GUARD-1113-01.json`. The record is byte-identical at its sealing commit `84b084dd8` and at `HEAD` (blob `588d5437a3f3`). On `git rev-list --ancestry-path 84b084dd8..HEAD`, `git diff-tree -m` lists the record for two merges: `9b2a7369e` (#457 on `1.1.x`; its tree equals its second parent and the first parent is an ancestor of it, so ADR 0061 exempts it) and `beb32b930`, whose tree equals neither parent because wave 2 carried ten documentation-only commits of its own; no exemption applies.
Expected: merging the trunk into a branch that has no records of its own does not invalidate the trunk's sealed records. The 1.1.13 board working rules (2026-09-26) allow merging the trunk into a branch before its admission commit; under the current validator that holds only when the branch has no commits of its own or the trunk sealed nothing since the branch point.
Evidence: the verifier run above; the `rev-list`, `diff-tree -m`, tree and `merge-base --is-ancestor` checks recorded in the WS-GOV log checkpoint of 2026-09-26 (`docs/handoff/1.1.13/WS-GOV.md` on `feature/1.1.13/ws-gov` until it integrates).
Owner: commander (branch topology); root fix in WS-GOV (ADR draft `docs/handoff/1.1.13/ADR-DRAFT-governance-reset.md` on `feature/1.1.13/ws-gov`, retiring history replay).
Workaround (proposed, not applied): rebuild wave 2 as its own documentation-only commits rebased onto `9b2a7369e`, without the merge commit, then rebase the branches built on it (including `feature/1.1.13/ws-gov`). Until the WS-GOV fix lands, bring the trunk into a diverged branch by rebase, not merge, whenever the trunk sealed records after the branch point. Rewriting a pushed branch needs the owner's approval.
Resolution: not fixed.
