## 1. 結論

1. **R11-01：4 retain、3 simplify、1 delete 候選。** 唯一具備靜態無 caller 證據的是 `AbMergeByIc` accessor；不能擴大為刪除整個 registry。General planner、JSON／pre-built admission、單 caller formatter 及 Dummy DP 選項都有具體契約或 consumer，不能僅因名稱、層數或 caller 數量判為冗餘。F06 須處置既有 Application enum，F07 須涵蓋三類 protection consumers；證據及刪除條件見第 3 節。
2. **R11-02：既有 vocabulary 可沿用，但新增 IC 仍須新增明示資料與獨立准入證據。** NT51929 Standard Merge 與 NT51950 AB Merge 展示了不同 map、topology、metadata、processor 及 evidence 契約，不能互相複製 support 結論（`SPEC.md:1332`、`:1364`；第 4 節）。
3. **B-01 仍是適配邊界，未證明現行 IC 不可見。** 此 HEAD 已有獨立 `familyDisclosureFamilies`，但 disclosure 的 IC 集合仍明文受 Standard registry 限制；AB selector 則取 compiled capabilities／routes。目前十個 runtime IC 全都有 Standard registration，沒有現成的 AB-only 代表案例。若後續 onboarding 納入不帶 Standard registration 的新 IC，須先決定是否擴充現有 disclosure owner（`docs/contracts/profile-bundle-package-trust-index-v1.md:30`、`:41-42`；第 5 節）。
4. 找到兩項 onboarding 文件差異：指南未註明 AB primary FWConfig 例外；supported matrix 的 NT51950 詳細列仍把全部 AB routes 稱為 Supported。兩者均以現行 ADR／exact-route policy 為準，列為文件修正輸入，不提出 firmware 行為修改（第 6 節）。

## 5. B-01：Standard-rooted disclosure 驗證

全索引核對顯示，本 HEAD 的 runtime registrations 共涵蓋十個 IC：NT51917、NT51919、NT51923、NT51926、NT51927、NT51928、NT51929、NT51932、NT51950、NT51951；十者皆有 `standard-merge` registration（`profiles/built-in/package-trust-index.json:513-724`）。`ab-merge` 的五個 IC 為 NT51919／NT51929／NT51932／NT51950／NT51951（同檔 `:651-702`）；`ctrlram-replace`、`general-merge`／`general-replace` 的 IC 也全在上述 Standard 集合內（同檔 `:22-486`）。因此沒有任何現行 IC 可充當 AB-only、CtrlRAM-only 或 General-only 代表案例；本次只能對該新增情境作條件式靜態推導。

| 情境 | 核對結果 | 證據與判定 |
| --- | --- | --- |
| 現行 NT51929 Standard | Standard key 存在；family facts 可由明示 disclosure provider 加入 | `profiles/built-in/package-trust-index.json:596`、`:627`；`I/Composition/CanonicalCapabilityDisclosureInventory.cs:26`、`:173`。**已核對來源鏈，未執行 UI** |
| 現行 NT51950 AB | AB registration 與 Standard registration 同時存在；AB topology choices 不依 global Number dictionary | `profiles/built-in/package-trust-index.json:684`、`:717`；`A/Capabilities/CapabilitySelectorPublication.cs:238`。**不能以此樣本宣稱 AB-only 已受支持** |

關鍵區分：

- **獨立 family provider 已存在，但 IC universe 尚未解耦。** 現行契約明寫 Standard registry 繼續決定 disclosure universe，因此這是 onboarding 契約邊界，不是已證明的現行契約違反（`docs/contracts/profile-bundle-package-trust-index-v1.md:41-42`）。
- **AB 動態編譯不在此處查 Standard registration。** `BuiltInV2DynamicCompilationAdapter` 對 AB 使用 `FindAbMergeRegistration(identity.IcId, identity.MapVariant)`（`src/NvtFwCombiner.Infrastructure/Composition/BuiltInV2DynamicCompilationAdapter.cs:132-134`）；同檔 `:187` 的 `StandardMergeByIc[icId]` 僅位於 `ExperienceIds.StandardMerge` 分支。這支持上述條件推導，但不證明新增 AB-only bundle 的全部 admission／publication 路徑已成功。
- **Number 不是一律受此耦合影響。** CtrlRAM 使用 disclosure choices；General Replace 使用 route choices；AB 使用 topology projection（`src/NvtFwCombiner.Application/Capabilities/CapabilitySelectorPublication.cs:218`、`:227`、`:238`）。一般 choices 由宣告的 postbuild `PlanSelectors` 投影，沒有 profile 時回 single，並非檢查外部工具當下是否存在（`src/NvtFwCombiner.Application/FlashMaps/IcNumberChoicePolicy.cs:27`）。
- 既有 family-disclosure 測試驗證移除 DP definitions、provider opt-in 及 conflict／reload；其 Standard registry 仍存在，不能作為 AB-only coverage（`tests/NvtFwCombiner.Bootstrap.Tests/CanonicalFamilyDisclosureSourceTests.cs:17`、`:51`、`:85`）。

**建議**：目前路由 retain；若 owner 將「無 Standard registration 的 IC」納入後續 onboarding，先 extend 現有 disclosure materializer／contract，明定 IC 集合及 missing-family 表示，再補 AB-only、CtrlRAM-only、明示 Standalone、provider conflict、reload 保留舊 publication 的驗收。不能新建平行 IC registry，也不能僅擴大 keys 後保留 disclosure materializer 內 `StandardMergeByIc[icId]` 的強制索引（`src/NvtFwCombiner.Infrastructure/Composition/CanonicalCapabilityDisclosureInventory.cs:107-108`）。
