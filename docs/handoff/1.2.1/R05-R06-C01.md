## 4. R06-01：來源、locator、transport／auth 與 publisher 契約

### 4.1 來源選擇與 precedence 提案

**Locator 選擇、Registry 內的來源改向、durable manual pin 是三個不同層次。** 以下明文化既有規則；不新增外部 production locator loader（`docs/adr/0053-fixed-update-source-registry.md:75`、`:86`、`:125`；`docs/handoff/1.1.14/1.2.x-inventory.md:183`）。

| 層次 | 契約 |
| --- | --- |
| **Locator precedence** | Direct Desktop 明示 `--update-source-registry-path <value>` → inherited `NFC_UPDATE_SOURCE_REGISTRY_PATH` 非空白值 → compiled-in `ProductionDefaults` primary/backup。明示 override 替換整組 defaults，不合併；無效 override 不靜默退回 defaults。Distribution Launcher 使用 env/default seam，不能假設它接受 Desktop 的診斷 option。**現行兩個 defaults 是 `G:` 磁碟代號路徑，並非 UNC literal**；package 固定的是字串，不是各 client 的磁碟映射或最終解析目標。依據：`src/NvtFwCombiner.Bootstrap/UpdateSourceRegistryLocator.cs:7`、`:14`；`src/NvtFwCombiner.Bootstrap/ManagedDistributionLauncherHostServices.cs:215`；`docs/contracts/update-source-registry-v1.md:17`、`:153`。 |
| **Registry replica 選擇** | primary/backup 是同一 logical publication；選可接受的最高 `registryRevision`，同 revision／同 bytes 才優先 primary；同 revision 異 bytes fail closed，不依時間戳，不合併文件。依據：`docs/contracts/update-source-registry-v1.md:32`。 |
| **Registry 內選源** | `latest`，再依宣告順序嘗試 `available`；不自動選 `deprecated`。每個 source admission 沿既有 Catalog／package verifier、writer lease、重讀與 atomic commit。ADR 記載的現行 Catalog 同樣使用 `G:` 路徑，不能將其部署信任簡化為純 UNC。依據：`docs/contracts/update-source-registry-v1.md:78`；`docs/adr/0053-fixed-update-source-registry.md:208`。 |
| **Manual pin** | Browse/Confirm 的 durable pin 暫停 automatic Registry selection；不是另一個 Registry locator。Resume 成功 admission／commit 才清 pin；失敗保留 pin、source 與已接受 revision/digest。依據：`docs/adr/0053-fixed-update-source-registry.md:86`；`docs/contracts/update-source-registry-v1.md:219`。 |
| **只搬 Catalog/package** | compiled-in locator 不變；複製相同內容、核對 identity，再以較高 Registry revision 改向。回切也用更高 revision；同 package bytes 可維持 package identity。依據：`docs/handoff/1.2.1/R03-launcher-plan.md:151`。 |
| **Registry 本身搬站／改 defaults** | rebuilt package 帶新 compiled-in defaults；舊站仍須讓支援 client 取得它，保留雙站至矩陣內 client 過渡完成。**即使後端內容不變，將 defaults 從磁碟代號改成 UNC 仍須 rebuilt、重新識別的 package，並驗證舊新 locator 過渡。** A1a 若要求 UNC-only，須將此條件列入輸出交 owner 決定。舊站先消失時不承諾零操作遷移；此路徑不授權覆寫 Root Bootstrap。依據：`docs/contracts/update-source-registry-v1.md:17`；`docs/handoff/1.2.1/R03-launcher-plan.md:152`。 |

| 層次 | 契約提案、現況與限制 |
| --- | --- |
| **file／UNC，主案** | Local file 由 OS 存取檢查；UNC 使用執行者 Windows identity，服務端以 share＋NTFS effective ACL 授權讀取。**固定來源的 compiled-in locators 與文件記載的 Catalog 是 `G:` 磁碟代號路徑**；實際 provider、映射供應方式、每個 user/session 的解析目標，以及誰能刪除／重映射，均須無條件納入 A1a。目的 share 的 ACL 不控制 client 如何將磁碟代號改指另一目標。Registry、Catalog、package 及其可替換父路徑亦須納入。來源可為 UNC，不代表 managed installation root 可為 UNC；後者仍須 local fixed drive，root 與既有 ancestors 均 non-reparse。依據：`src/NvtFwCombiner.Bootstrap/UpdateSourceRegistryLocator.cs:7`；`docs/adr/0053-fixed-update-source-registry.md:208`；`docs/adr/0062-first-run-managed-setup.md:288`。 |
| **HTTPS，唯一首套認證提案** | 建議 **Windows Integrated Authentication：Negotiate，限定 Kerberos**，使用 OS 登入 identity；不新增產品密碼庫，不默退到 NTLM／Basic／匿名。這是待 owner 依部署事實核准的具名方案，**不是已存在能力或 decision 188 已選定的認證**。`Negotiate` 名稱本身不能作為 Kerberos-only 證據；F14 須明訂可驗證的 client 限制／server 停用 NTLM 強制點，並驗證 Kerberos 不可用時拒絕而非降級。若現場不適用，O2 可改選 **Entra ID／OAuth 登入與 token 授權**類別下的一個具名方案，取代本提案，仍只驗收一種認證。依據：`docs/handoff/1.2.x.md:71`；`docs/architecture/launcher-update-proposal-20260923.md:89`。 |

| **Case A／B gate** | ACL-only 只有 A1a 成立、A1b 確認才可採；須涵蓋 server ACL、publisher，以及 client 映射／override 改向面。需抵抗不可信 mirror／可改 metadata 的外部發布者，或控制邊界不成立，依 Q4 轉 Case B。缺事實先列未閉合，不自動當成 Case A 通過；簽章案仍須獨立閉合 trust root、rotation／revocation／expiry 與遷移契約。依據：`docs/handoff/1.2.x.md:75`；`docs/handoff/1.2.1/R03-launcher-plan.md:100`、`:189`。 |

### 4.3 拒絕矩陣與 D7 replay 限制

下表的「拒絕」通常指該讀取／候選不能 admission；只有既有選擇 policy 可續試已宣告候選。拒絕本身不授權改 source、重置 high-water 或自動安裝；exhaustion 保留 committed state／offline 能力（`docs/adr/0053-fixed-update-source-registry.md:32`）。

| 情境 | 必須結果／限制 | 依據 |
| --- | --- | --- |
| override malformed、relative／device／ADS／reparse、unsupported scheme | typed invalid／unsafe；不搜尋 share，不借 defaults 掩蓋 override 錯誤。 | `docs/adr/0053-fixed-update-source-registry.md:125`、`:172`；`tests/NvtFwCombiner.Bootstrap.Tests/UpdateSourceRegistryLocatorTests.cs:21`。 |
| share ACL 拒絕、來源消失、timeout | typed permission／unavailable／timeout；失敗不變更 durable source；健康本機啟動仍可用。 | `docs/adr/0053-fixed-update-source-registry.md:141`、`:181`。 |
| HTTPS 401/403、200 HTML/login page、redirect | 既有 Registry 將 401/403 與 HTML/login page 判為 `AuthenticationRequired`。**現行 reader 最多跟隨 5 次 redirect，只驗下一站為合法 HTTPS locator，沒有同 origin 比較；production client 未設定 credentials。** F14 須將同 origin 規則同步套用 Registry reader，並驗證 Catalog/package 的失效認證、TLS 驗證失敗、跨 origin redirect 拒絕及無 credentials 外送；不降級 HTTP／auth。 | `docs/contracts/update-source-registry-v1.md:71`；`src/NvtFwCombiner.VersionManagement.Infrastructure/VersionManagement/HttpUpdateSourceRegistry.cs:12`、`:65`、`:128`、`:226`、`:241`；F14：`docs/handoff/1.2.1/R03-launcher-plan.md:48`。 |

| 舊 Catalog 不符當前 publication assertion | latest version、schema 或 exact Catalog SHA 任一不符即拒絕；Catalog 沒有自己的 revision。 | `docs/contracts/update-source-registry-v1.md:61`；`docs/handoff/1.2.1/R03-launcher-plan.md:83`。 |

| 有界限制 | 精確含義 |
| --- | --- |
| 首次 admission 前沒有 durable high-water | null source／缺 Registry state 等情況，automatic no-candidate check 可作兩次一致性檢查，卻不跨 restart 記住新 revision。不能宣稱抵抗此前所有歷史 replay。`docs/adr/0066-update-catalog-v2-notification-policy.md:101`。 |

| 稽核、撤權與再發布不是 runtime 自動保證 | editor 可產生更高 revision 的原子 Registry 更新，但不證明現場能及時發現入侵、撤銷權限或恢復安全 publication。撤權也不等於已接受／已下載內容自動失效；角色、時效與限制須由 A3／A9 提供證據並交獨立審核。`docs/contracts/update-source-registry-v1.md:128`、`:162`；`docs/adr/0053-fixed-update-source-registry.md:96`。 |

## 5. C01-1：cold health deadline 政策

### 5.1 已核實現況與 ADR 0062 文字提案

現況 `DefaultHealthObservationDeadline = ProgressDelay`，payload admission、state load、root observation 共用此 deadline。歷史 bug 記錄一次 **262.0998 ms** 的 health cancellation，當時 root observation 尚未完成；它不是此 HEAD 的實包 benchmark，也未證明每次 shipped startup 都失敗（`src/NvtFwCombiner.VersionManagement.Application/VersionManagement/ManagedLauncherEntry.cs:450`、`:528`、`:797`；`docs/handoff/bugs/BUG-20260928-b2-joint-recovery-entry-health-unavailable.md:48`、`:155`）。

**現行可觀測性限制：** `ManagedLauncherEntryResult` 只有 `Outcome`、`ManagedRoot`、`AdmissionElapsed`、`TotalElapsed`，沒有 reason。health deadline 逾時、root probe 的 `PermissionDenied`／`Unavailable`，以及部分 state-load 失敗都回 `HealthUnavailable`；admission deadline 的部分路徑也共用此 outcome。因此控制流可以分開「觀察未完成」與「已確定不可觀測」，但現行 terminal result／exit code 13 不足以供使用者或量測者區分，不能從 elapsed 或 root 是否為 null 反推原因（`src/NvtFwCombiner.VersionManagement.Application/VersionManagement/ManagedLauncherEntry.cs:437`、`:542`、`:785`、`:844`、`:853`；`docs/handoff/1.2.1/R03-launcher-plan.md:85`）。

**ADR 0062 擬替換／補充的政策：**

| 條款 | 提案 |
| --- | --- |
| **兩個時間參數** | `ProgressDelay = 250 ms` 只控制非阻塞 progress。獨立 hard health cap 記為 **H**；H 由 `1.2.6` packaged cold-start 證據交 owner 核准，本報告不預填毫秒值。依據：`docs/handoff/1.2.x.md:66`。 |
| **一個觀察預算** | payload descriptor projection、state load、exact-root observation 共用從該次 entry 開始計的 absolute monotonic H；進下一階段不重設計時。耗時超過 250 ms 本身不能變成 health failure。依據：`docs/adr/0062-first-run-managed-setup.md:123`；`tests/NvtFwCombiner.Application.Tests/VersionManagement/ManagedLauncherEntryCoordinatorTests.HealthDeadline.cs:46`。 |
| **減少 cold work** | 在既有 payload／schema owner 預先計算可證明不隨 invocation 改變的工作；不得以 prior healthy cache 取代當次 state/root 或執行碼驗證，也不得將 runtime 初始化移出計時而宣稱改善。實包量測須列出 pre-entry 初始化成本。依據：`docs/handoff/1.2.x.md:68`；`docs/adr/0062-first-run-managed-setup.md:61`、`:138`。 |
| **逾時與 Retry** | 純粹「觀察仍未完成」只有達 H 才回 `HealthUnavailable`＋Retry。Retry 是新一次有界 entry observation，不跳過驗證、不取得 repair/delete 權、不形成無界並行讀取；前次遲到結果不得改新 session、寫 state 或啟動程序。依據：`docs/adr/0062-first-run-managed-setup.md:201`；`docs/handoff/1.2.1/R03-launcher-plan.md:74`。 |
| **已確定失敗** | 提案將 Q2 的「only past cap」限定於**因緩慢而失敗**。payload invalid／unavailable、recovery facts 或 busy 沿各自 typed outcome；state/root 的 permission／unavailable 立即返回 `HealthUnavailable`，不等待 H，也不當成 damaged。**現行 outcome 不帶上述原因區分**，須依 O4 補足，不能宣稱既有產品已精確呈現原因。依據：`src/NvtFwCombiner.VersionManagement.Application/VersionManagement/ManagedLauncherEntry.cs:803`、`:829`、`:853`；控制流解讀交 O3 確認。 |
| **原因與診斷來源** | **建議採 O4-A：**由 `ManagedLauncherEntryCoordinator` 在作出 terminal 決定時，讓 entry result 攜帶 typed reason／stage，診斷記錄消費同一結果；至少區分 health `deadline-exceeded`、已確定 `permission-denied`／`unavailable`，並保留可用的 upstream typed issue。admission timeout、caller cancellation 與 health timeout 分開記，不靠 UI、elapsed 或 exit code 重推。這是 C01-2 的 R2 Application result contract 提案，不新增 durable state，須同步 ADR 0062 與 consumers；正式欄位／enum 命名留有界實作設計。現況依據：`src/NvtFwCombiner.VersionManagement.Application/VersionManagement/ManagedLauncherEntry.cs:437`、`:443`、`:542`、`:785`、`:844`。 |
| **其他 deadlines 保持各自 authority** | H 仍須容納於既有 entry admission operation budget，保留 hashing／handoff 與 cleanup 空間。5.5 s admission、45 s completion、candidate／LKG 各 20 s READY，以及 writer wait 不因 H 自動放寬；不足時另帶量測回 owner。既有 P95 100/300/750 ms targets 亦不能以新 H 宣稱通過。依據：`docs/adr/0062-first-run-managed-setup.md:147`、`:191`。 |

### 5.2 狀態與轉移

下列是擬議政策；`Checking`／`slow-but-healthy` 是說明名稱，不要求新增 durable state 或 enum。reason／stage 區分依 O4 決定，尚非現有 result 能力。

| 觀察／事件 | 轉移與可見狀態 | 安全界線／依據 |
| --- | --- | --- |
| 開始，未到 250 ms、未完成 | `Checking`；不因短暫等待顯示 failure。 | progress delay 的既定用途：`src/NvtFwCombiner.VersionManagement.Application/VersionManagement/ManagedLauncherEntry.cs:449`。 |
| 250 ms 已到、仍在 H 內 | 顯示非阻塞 `Checking installation...`，繼續同一次觀察。 | 不重設 H、不啟動第二次觀察。政策依據：`docs/handoff/1.2.x.md:66`。 |
| 健康事實完整，於 H 內完成 | 正常 handoff；若曾跨 250 ms，記為 **slow-but-healthy**，不是 recovery。 | 健康分類仍走 exact code／Bootstrap admission，progress 不是 READY。`docs/adr/0062-first-run-managed-setup.md:82`、`:110`。 |
| H 到達而 observation 未完成 | `HealthUnavailable`＋Retry；本次不 handoff。依 O4 記 health deadline 原因。 | 晚回傳不能授予啟動／mutation 權。`docs/adr/0062-first-run-managed-setup.md:201`；`src/NvtFwCombiner.VersionManagement.Application/VersionManagement/ManagedLauncherEntry.cs:542`。 |
| payload invalid／unavailable、state/root permission／unavailable、busy | payload 沿 `PayloadInvalid`／`PayloadUnavailable`；busy 沿 `Busy`；**state/root permission／unavailable 立即返回 `HealthUnavailable`，不等 H，其與逾時的區分見 O4。** 不將不可觀測概括成安裝損壞。 | 現行 outcome 對 permission／unavailable 並未保留獨立 reason。`src/NvtFwCombiner.VersionManagement.Application/VersionManagement/ManagedLauncherEntry.cs:414`、`:803`、`:844`、`:853`。 |
| 已知 residue、root/state mismatch 等 recovery facts | `RecoveryRequired`；只有帶 exact root 才提供 root-bound recovery session。 | `HealthUnavailable` 不轉成 action。真正 mutation 仍須 diagnosis、immutable plan、writer lease 與重驗。`src/NvtFwCombiner.Bootstrap/ManagedDistributionLauncherHostServices.cs:300`；`docs/adr/0065-managed-setup-recovery-execution.md:29`。 |
| state/root／marker／staging 確實全部 absent | `ShowSetup`／`SetupRequired`。 | timeout、unknown 或「只少 state」都不能推成未安裝。`docs/adr/0062-first-run-managed-setup.md:88`、`:93`。 |
| Caller cancel／Retry | cancel 保持 cancel；Retry 重跑完整 observation，忽略舊結果。 | 不把 caller cancellation 記成 health failure；需保留 no-late-start。`tests/NvtFwCombiner.Application.Tests/VersionManagement/ManagedLauncherEntryCoordinatorTests.HealthDeadline.cs:230`；`docs/adr/0062-first-run-managed-setup.md:201`。 |

### 5.3 `1.2.6` 量測、cap 決定及驗收
