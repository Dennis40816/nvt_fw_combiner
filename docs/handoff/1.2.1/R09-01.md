## 1. Conclusions

The owner boundaries deemed "correct" by the 2026-09-09 baseline (accepted session, typed draft, Report does not recompute firmware facts, a single Application `MemoryLayoutProjector`) still hold at `6703e2517`. This assessment found no path where Presentation reads bytes, calculates ranges, or rewrites canonical region facts itself. Remaining duplication is concentrated in three areas: (1) **The Presentation Memory Layout rendering layer re-derives fill roles, plan action, source kind, "initialization vs unassigned", and kept decisions from `SourceSpaceId` (address space)**, forming a second classification path parallel to Application `MemoryLayoutProjector` (A-06–A-09, A-11, spread across `UiCompositionRunner.Common.cs`, `ShellTextResources.MemoryLayout.cs`, `ShellTextResources.DynamicText.cs`, and `ReplaceRegionGroupBuilder.cs`); (2) **A second readiness path in which Presentation decides pending/blocked itself when there is no exact capability** (C-06, `GetPendingMemoryDisplay`); Application already has a pending owner based on typed slot lifecycle, but its entry point requires a resolved capability, so this is an owner contract gap; (3) **Multiple Profiles versions coexist for the same `familyId`** (three versions of `nt51929-nt51932`, two of `nt51923-nt51926`, and two of `nt51917-nt51927-nt51928-canonical-container`). After normalization, only some subdefinitions (regionSets, some metadataSets/imageMap) are identical, and this head already has `definitionReference` version/hash pins through which newer versions consume older ones. Thus these are not "wholly interchangeable definitions", but "proven identical subdefinitions + legitimate version differences + pinned consumers" (A-01–A-03); the three NT51919/29/32 AB recipes have equal `operations`/`views`/`inputSlots`/`output`, but each pair has 9 leaf differences, 6 of which are member evidence (A-04). After caller tracing, Standard-rooted disclosure coupling (B-01) and workflow-specific Number sources (B-02) **do not establish** that "new ICs are invisible" or "Number is derived from tool availability"; they are reclassified as a coupling record and legitimate differences. Apart from C-06, there is no newly proven duplication in the input snapshot, accepted run state, or UI draft categories; existing gaps are already scheduled under R02-01, R18-01, and R17-02 respectively. Recommendation: use A-06–A-09, A-11, and C-06 in R09-02 for **boundary and acceptance planning** of the first migration batch (implementation is not authorized in this round); route A-01–A-05 to R10 to assess adding shared regionSet/recipe references while retaining the existing metadata `definitionReference` seam; route B-01 to R11-02 for a decision after validation with representative ICs.
