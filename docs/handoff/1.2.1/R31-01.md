## 1. 結論

**repository 已能交付 Header／Header-copy 的幾何、處理路徑及 32-byte 差異根因盤點；尚不能完成 R31-01 的 firmware-owner facts 驗收。** O21 明列 reader 未明，decision 161 也保留此項作為任何安全聲明的前提。本次沒有取得補足它的新 firmware-owner evidence（`docs/handoff/1.1.14/1.2.x-inventory.md:502`；`docs/handoff/1.1.12.md:981`）。

可準確轉述：owner 曾判斷**已調查的 NT51950 AB Header／Header-copy CRC 差異不影響 firmware operation**。不能將它擴大為所有 IC、topology、bank、boot fallback 或 recovery 都安全，也不能由 CRC 重算有效推定 Header copy 未被使用（`docs/handoff/1.1.12.md:982`；`docs/handoff/1.1.13.md:110`）。

現行 Partial-family AB CtrlRAM Replace 的 B finalizer 只重定位 **ILM／DLM address** 並重算 **Header CRC**；ILM／DLM CRC 不在其寫入權限內，沿用 local postbuild 結果。這項區分直接影響 R08 對各 stage 責任與 CRC 行為的比較（`src/NvtFwCombiner.Profiles/V2/V2CompositionPlanCompiler.RuntimeReferenceReplace.Banks.cs:386`、`:387`、`:388`）。

`1.2.5` 應依既定順序，以本報告及 owner facts 支援 R08-01／02，再分別決定 R31-02 reset policy 與 R31-03 allowance；firmware facts、reset policy、Golden allowance 是三個獨立決策，盤點不預授權修復（`docs/handoff/1.1.14/1.2.x-allocation.md:172`；`docs/handoff/1.1.14/1.2.x-inventory.md:457`）。

## 3. Header／Header-copy 宣告與位址

以下均為半開區間。CtrlRAM family maps 的 canonical address space 是 `flash`；catalog copy offsets 是交給 postbuild 的 staged firmware image 檔案位移。AB 的 bank-local offset 必須加上所選 map 的 bank placement，不能把它直接當成整張 AB output 位址或 SRAM 位址（例如 `profiles/built-in/nt51950-ctrlram-replace-candidate/families/nt51950-ctrlram-replace.json:15`；`src/NvtFwCombiner.Profiles/V2/V2CompositionPlanCompiler.RuntimeReferenceReplace.Banks.cs:245`、`:274`）。

## owner 需決定的問題

請本專案 owner **以 firmware owner 身分**回答以下六題：Q1、Q2、Q3、Q3b、Q4、Q5。可以直接選項回覆，不需閱讀 NFC code；請附適用 IC、IC 數量與 firmware 版本，不知道的部分保留 `unknown`。可複選題中，「皆不讀／不檢查」不與其他實質選項並選。

以下「copy」指 `FLASHMAP_HEADER_COPY`；「一輪 postbuild」指製作 TP 時的一次 Combiner 處理；「B 地址正規化」指先將 B 的地址換回以該 bank 起點為基準的地址，再執行 local postbuild。這些問題是在取得 firmware 契約，沒有預設 reset 或 refresh 已獲核准。

**Q1：誰會讀取 Header copy，何時讀？**

- **讀取者，可複選**：A. 啟動程式（boot ROM／bootloader，請註明）；B. 運作中的 firmware；C. 燒錄／升級／離線工具；D. 上述皆不讀；U. `unknown`。
- **每個讀取者的時機，可複選**：A. 一般啟動；B. 主 Header 檢查失敗或 recovery（請註明條件）；C. 切換 bank；D. 僅製檔／燒錄／升級時；U. `unknown`。

答案決定 R08 是否需要 boot／recovery 的失敗案例；只觀察到一般操作正常，不能代答其他時機。未決來源：`docs/handoff/1.1.13.md:115`；`docs/handoff/1.1.12.md:986`。

**Q2：讀取者驗哪些 CRC、何時驗；不符時怎麼處理？**

- **檢查內容，可複選**：A. copy 自身的 Header CRC；B. copy 所存 ILM／DLM CRC 是否符合實際內容（請註明哪個）；C. main DLM CRC，包含其中的 copy；D. 只讀資料、不檢查 CRC；U. `unknown`。
- **檢查時點，可複選**：A. 載入／執行前；B. 每次一般啟動；C. 切 bank 或 recovery（請註明）；D. 僅製檔／燒錄／升級時；U. `unknown`。
- **不符時的處理**：A. 停止啟動或操作；B. 改用主 Header 或另一 bank（請註明）；C. 進 recovery；D. 忽略並繼續；U. `unknown`。不同讀取者可分別回答。

答案決定 R08 的完成條件與失敗案例；若會比對最終 DLM，R31-02 就必須納入 copy 的生成要求。依據：`docs/handoff/1.1.13.md:110`、`:116`。

**Q3：copy 應保存哪個階段的 Header？B-copy 裡的地址應以哪裡為起點？**

- **copy 內容**：A. 前一輪 postbuild 的 Header 快照；B. 與最後產出的 main Header 同步；C. 只有指定欄位有效（請列名稱）；U. `unknown`。
- **B-copy 地址**：A. 以 B bank 自己的起點為零（bank-local）；B. 以完整 AB 映像起點為零；C. 依 IC／讀取者而異（請列適用組合）；U. `unknown`。
- **若不同製檔流程會影響答案**：請補 SVN 在 copy 前或後更新，以及 copy／CRC 初值由哪個製檔步驟建立；不清楚可答 `unknown`。

答案支援 R08 比較 CRC-only 與完整 normalize→postbuild→restore，也限定 R31-02 的 copy 順序與保留欄位。依據：`docs/handoff/1.1.13.md:114`、`:116`；`docs/architecture/nfc_roadmap.md:1165`。

**Q3b：A／B 使用同一份 TP 時，哪些 CRC 應相同？第一輪 copy 前，CRC 應處於什麼狀態？**

- **A／B 相等要求**：請對 **main Header CRC、main DLM CRC、copy Header CRC、copy DLM CRC** 四項分別選：A. 必須相同；B. 不要求相同；C. 依 IC／處理階段而異；U. `unknown`。請註明答案適用「換回 bank-local 地址後」或「最終 AB 映像」；若四項皆無要求，可直接答「皆不要求」。
- **第一輪 postbuild 前的 ILM／DLM／Header CRC 初值**：A. 全部清零，與 fresh build 相同；B. 依正規化後的內容重算（請列欄位）；C. 保留輸入原值；U. `unknown`。
- **B 地址換回 bank-local 後、複製 Header 之前，Header CRC 是否必須先 refresh？** A. 必須；B. 不必；C. 依 IC／流程而異（請列條件）；U. `unknown`。

答案直接決定 R31-02 的 reset／refresh 選項，以及 R08 應在哪個階段要求 A／B CRC 相等。依據：`docs/handoff/1.1.13.md:117`、`:118`；`docs/handoff/bugs/BUG-20260926-b-normalization-stale-header-crc.md:14`。

**Q4：decision 161「不影響操作」的判斷，確切適用哪些產品與使用情境？**

- A. 僅維持當時已調查的 NT51950 Normal／Both 案例。
- B. 適用 NT51950 的其他指定版本或情境，請列明。
- C. 可擴及其他指定 IC／IC 數量／bank 選擇／AB format，請逐組列明。
- U. `unknown`，目前無法確認適用範圍。

請補 firmware 版本、single／cascade、A-only／B-only／Both、Common／Desay，以及不包含的 boot／recovery 情境。三份 TP 根因樣本不自動代表上述組合皆已驗證。答案限定 R08 驗收矩陣與 R31-02 的 IC／bank／mode／range。依據：`docs/handoff/1.1.13.md:42`、`:100`、`:122`；`docs/handoff/1.1.14/1.2.x-inventory.md:342`、`:343`。
