## 1. Conclusions

The only cross-family reference at `d5770e52e` is metadata structure `definitionReference`: four exact values (ADR 0040 `:78-92`; `firmware-family-v1.md:196-204`), with the trust index's `metadataProviderFamilies` specifying the sole provider bundle (contract `:17-20`); within the provider's normalized catalog, id + version + hash locate the family, and `ReferenceEquals` shares the same immutable definition (`src/NvtFwCombiner.Infrastructure/Composition/BuiltInV2Bundle.cs:331-354`). Inventory: 18 of 19 family source files contain references, totaling 41 occurrences and 6 exact targets `(familyId, familyVersion, structureId)`, all across bundles; including 5 materialized copies from the trust index's `canonicalFirmwareFamily` gives 23 files/56 occurrences (3.4). It does not cover regionSets or profile recipes; current rejections are spread across four layers (3.3); the guarantee against cross-bundle cycles is a static layer table plus tests on build artifacts, rather than runtime typed rejection.

Recomputation confirms R09-01's A-01–A-05: one complete regionSet group each in A-01 and A-02 and three in A-03 are identical; A-03 also has three identical metadataSets and one identical imageMap; each pair among the three NT51919/29/32 AB profiles has 9 leaf differences, all member identity/map/evidence, while the other 9 blocks are equal key by key (section 4). **Only regionSets and the AB recipe are reference candidates in this assessment**; this does not mean “only these are duplicated”.

Proposed contract (section 5): retain the model of “exact id + version + content hash + target id, sole provider, closed schema, no overrides”, adding family `regionSetReference` and profile `recipeReference`. Expansion uses JSON within Infrastructure's document projection (S1′); the complete expanded document is revalidated against the same consumer-selected schema by the same validator, then passes to DTO and normalizer; v2.17's 12 cross-block `allOf` rules therefore remain unchanged (5.4). The recommended recipe owner is a neutral `composition-recipe` document in the same bundle (option A). Equivalence evidence (5.6): recursive equality of all `CompiledComposition` members before and after each member's migration (identity locations are recomputed and compared under 5.6's identity transformation table; completeness is proved by a member classification table, fingerprint input mapping and negative cases for omitted comparisons, P1), fingerprints recomputed from the new bytes and re-pinned, complete Golden bytes, structural equality of Report `Operations`/`Mutations`/`OutputDifferences`, and equality of representative failure contracts; across members, compare only the 9 recipe blocks and verify that the 9 differences remain. Impact (5.7): A-04 changes not only the three AB routes but also the composite definitions and fingerprints of **six CtrlRAM AB bank Replace routes**; A-01/A-02 additionally propagate to General Merge candidate bundles and their saved-rule parents. Three matters cannot be closed in 1.2.1 and are listed as 1.2.5 prerequisites (section 7): the runtime dependency-graph guarantee for parallel preload (the owner chose parallel loading even for a non-build trust index in Q7, making this an **R3 prerequisite**), mechanical proof of comparer completeness, and the Golden/write-range evidence level for bank Replace (Q8 sets the migration gate; the firmware-owner records the acceptance boundary). The owner has answered Q1–Q8 in decision 235 (owner answers table). Literal `ref`/`recipeReference` are currently rejected at the trusted gateway by top-level `additionalProperties: false` in both schemas (`composition-profile-v2.17.schema.json:6`; `firmware-family-v1.3-full-image-metadata.schema.json:6`; `ProfileBundleLoader.cs:139`); they are not a feature until the owner approves the syntax and the trust index selects the new schema.

## 3. Existing seams

<a id="31-契約與-schema"></a>

### 3.1 Contracts and schemas

- Definitions and bindings are separate; inline and `definitionReference` are mutually exclusive (ADR 0040 `:50-76`; `firmware-family-v1.md:196-213`; schema `firmware-family-v1.3-full-image-metadata.schema.json:717-`). All four values must match one owner-approved provider; inferring a provider from relationships, filenames, PID, versions, hash similarity or golden evidence is forbidden (ADR 0040 `:88-92`); rejection list `:139-142`, ADR 0041 `:62-66`.
- Layer responsibilities: Contracts serializes, Domain owns immutable definitions and cycle rejection, Profiles normalizes through the resolver interface, and Bootstrap owns the allow-list (ADR 0040 `:120-137`); a provider change requires coordinated version and content hash updates (`:307-312`).
- A profile binds an exact family with the `mapBinding` triple (`composition-profile-v2.md:34-36`); a bundle selects one exact schema snapshot by manifest hash (`:20-21`); the selected schema owns required/null, closed unions and version shapes, and Profiles accepts only admitted shapes (`:66-75`); schema 2.15 precedent: “no implicit migration of existing profiles” (`:471-473`).
- Architecture guard `tests/NvtFwCombiner.Architecture.Tests/RepositoryBoundaryTests.ProfileSchemaTrust.cs:40-75`: `ValidateEntries` precedes `new TrustedProfileBundle(`, projection calls `ValidateAndClone(`, and the normalizer contains no shape-check strings.

3. Rewrite the guard: `ProfileSchemaTrust.cs:40-75` retains “S1 precedes `new TrustedProfileBundle(`” and adds “S1′ schema revalidation must precede any DTO/normalization consumption of expanded content”; projection is the sole expansion point.

### 5.8 Cycles, depth, layers and parallelism (N3, F6 corrections)

- Separate the cross-bundle load DAG from the within-bundle document reference graph: recipe (option A) has depth 1 by schema construction; option B checks the donor at S1′; the regionSet provider target must be inline (S1′ `reference-depth-exceeded`); existing depth-2 metadata chains are not reopened. On-demand consumers (GM candidates) can only be consumers (`MatchesTrustIndex` requires excluded bundles to have no provider declarations, `BuiltInV2BundlePreload.cs:112-125`); their references are resolved by S1′ when opened and are not included in the preload table.
- Build time: the ADR 0077 generator traverses all `*Reference` occurrences in admitted documents (the traversal in `BuiltInBundlePreloadTests.cs:296-340`, extended to new kinds), builds the bundle dependency graph, and requires it to be acyclic with `Layers` in topological order; failure fails the build.
- **Prerequisite for runtime parallel preload (N3 correction)**: a build-time proof applies only to “the same documents as the build”. Current JSON fallback loads JSON using the **current** trust index's hashes when pre-built is rejected (`BuiltInV2Bundle.cs:44-52`); the trust index loader does not compare build identity (`ProfileBundlePackageTrustIndex.cs:135-150`); `MatchesTrustIndex` compares only directory sets (`:112-125`); the build identity comparison in `AcceptedPrebuiltProfileCatalog.cs:60-66` is used only for pre-built acceptance; ADR 0077 `:271-273` says only that other trust indexes do not use pre-built. JSON sources with the same bundle names but different hashes and reference graphs can therefore pass `MatchesTrustIndex`; the build-time DAG does not prove that graph. Revision 3 recommended `TrustIndex.ActualSha256 == BuiltInProfileBuildAdmissionIdentity.TrustIndexSha256` (`BuiltInProfileBuildAdmissionIdentity.cs:14-16,30-35,70-76`) as the parallel gate, otherwise serial (index hash binds entry-array hash, which binds document hash, `profile-bundle-v1.md:7-12`); **in Q7 (decision 235), the owner chose parallel loading even for non-build trust indexes**, so the gate becomes **runtime dependency-graph validation**, an R3 prerequisite for 1.2.5 (P2): (1) before any warm-up/worker that may recursively load a catalog, build the complete load dependency graph from admitted immutable snapshots bound by the current trust index—existing metadata, new regionSet references and actual load edges; separately validate within-bundle recipe depth—validation and workers must consume the same snapshots; (2) validate acyclicity and require every provider to be in a strictly earlier layer than its consumer, retaining bounded workers, warm-up and layer barriers (ADR 0075 `:53-65`); reject if unprovable (typed code, source path, deterministic order), never run in parallel with the old table; on-demand consumers must not become providers omitted from the graph; (3) retain the single-thread reentry guard, but it is **insufficient** to exclude mutual waits across workers; Q6's safety argument rests primarily on (1)(2).
- **What this report cannot close**: implementation, behavioral evidence and measured cost of runtime dependency-graph validation (section 7 P2); Q7 does not prove parallel safety or acceptable performance; ADR 0075's fixed-layer guarantee and ADR 0077's pre-built contract must record this extension.
- Layer correction: move A-02's consumer `nt51923-standard-merge` (layer 2, `BuiltInV2BundlePreload.cs:54`) after shared-facts (layer 3 with AB, or a new layer); do **not** move `nt51923-nt51926-shared-facts` (`:53`) earlier, because it still references layer 1's container 1.4.1 (`nt51923-nt51926-shared-facts/families/nt51923-nt51926.json:108-112`; `:49`). A-01 and A-03 are existing edges. Include all new edges in `EveryReferenceResolvesToAnEarlierLayer`.

## Limitations

1. Read-only static inspection; no builds, tests or verifier execution. All statements of “would currently reject” come from reading code and schemas.
2. Same-thread recursive behavior of `Lazy<T>` is inferred from .NET documentation, not reproduced with a fixture; 5.8 does not claim deadlock has occurred in the existing built-in graph, only identifies the boundary of the proposed guarantee.
3. 23/56 is the static expansion count from trust index and manifest declarations; the materializer was not run; the six bank Replace routes come from the policy list and call chain, without executing the catalog.
4. 340 in `canonical-capability-policy-v1.json` is a string occurrence count, not a route count; affected routes will be counted from actual bundles in R10-02.
5. Not all invariants in `NormalizeRegionSets`, `CreateMaps`, `ResolvePhysicalFacts` and the `FirmwareImageMap` constructor were read line by line; 5.6's member list and identity transformation table come from reading members of `CompiledComposition`/`V2CompiledCompositionDetails`/`V2CompilationContext`/`FirmwareMapResolutionResult`/`RuntimeReferenceBankReplaceV2CompilationContext`, and nested locations may still be missing; completeness is proved by P1's member classification table, input mapping and negative cases, not guaranteed by this report.
6. The internals were not checked to establish whether `ProfileBundleSchemaValidator`'s `JsonElement` evaluation seam (`:151-165`) can directly handle composed documents or the shape of the new `ValidateAndClone` entry point; 5.4 is an interface-level recommendation.
7. AB Golden inspection checked only manifest entries, route evidence `contract-only` markers and test templates; no case manifests were opened and no Golden cases were executed; the four-axis description of bank Replace evidence comes from reading test source (not executed; real Combiner cases are Windows-only), with the acceptance boundary left to Q8/P4.
8. Normalized JSON equality is not equivalent to expanded map/range or output-byte equivalence (same as R09-01 limitation 3); section 4 line ranges are inspected scope, not removable line counts.
9. The 1.2.6 online-update process for atomic provider/consumer re-pinning was not assessed; only ADR 0077 `:271-273,414-423` is recorded; UI/CLI consumption for displaying new catalog codes was not inspected; costs of build-time DAG checks, runtime dependency-graph validation and the serial control were not measured.
10. Owner decision 235 and the Q1–Q8 answers were relayed by the coordinator; `docs/handoff/1.2.x.md` at `d5770e52e` lacks this record, and this report did not verify the original wording; the identity transformation table lists locations currently identified from types, with unlisted locations added after P1 exposes them (this rule addresses the T2 residual without claiming completeness).
