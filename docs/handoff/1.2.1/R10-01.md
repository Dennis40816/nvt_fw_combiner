## 1. 結論

`d5770e52e` 唯一的跨 family 引用是 metadata structure 的 `definitionReference`：四值精確（ADR 0040 `:78-92`；`firmware-family-v1.md:196-204`），由 trust index `metadataProviderFamilies` 指定唯一 provider bundle（契約 `:17-20`），在 provider 的正規化 catalog 內以 id＋version＋hash 找 family、以 `ReferenceEquals` 共用同一 immutable definition（`src/NvtFwCombiner.Infrastructure/Composition/BuiltInV2Bundle.cs:331-354`）。盤點：19 份 family 來源檔中 18 份含引用，共 41 處、6 個精確目標 `(familyId, familyVersion, structureId)`，全部跨 bundle；加上 trust index `canonicalFirmwareFamily` 的 5 份 materialized 複本為 23 份／56 處（3.4）。它不涵蓋 regionSet 與 profile recipe；今日的拒絕分布在四層（3.3）；跨 bundle 循環的保證是建置產物上的靜態 layer 表＋測試，不是 runtime typed 拒絕。

R09-01 的 A-01～A-05 重算成立：A-01、A-02 各一組、A-03 三組 regionSets 整份相同；A-03 另有三組 metadataSets 與一個 imageMap 相同；NT51919／29／32 三份 AB profile 每對 9 個 leaf 差異，全部是 member identity／map／evidence，其餘 9 個區塊逐 key 相等（第 4 節）。**本次只把 regionSets 與 AB recipe 列為引用候選**，不是「只有它們重複」。

建議契約（第 5 節）：沿用「精確 id＋version＋content hash＋目標 id、唯一 provider、schema 閉合、不覆寫」模型，新增 family `regionSetReference` 與 profile `recipeReference`。展開在 Infrastructure 的文件投影（S1′）以 JSON 完成，展開後的完整文件以 consumer 選定的同一 schema、同一 validator 重驗，再 DTO、再 normalizer；v2.17 的 12 條跨區塊 `allOf` 因此原樣保留（5.4）。recipe owner 建議為同 bundle 的中立 `composition-recipe` 文件（選項 A）。等價證據（5.6）：每 member 遷移前後 `CompiledComposition` 全部成員遞迴相等（身分位置依 5.6 的 identity 轉換表重算比對；完整性以成員分類表＋fingerprint 輸入對照＋漏比負例證明，P1）、fingerprint 依新 bytes 重算並重新 pin、完整 Golden bytes、Report `Operations`／`Mutations`／`OutputDifferences` 結構相等、代表性失敗契約相等；跨 member 只比 9 個 recipe 區塊並驗證 9 個差異保留。影響範圍（5.7）：A-04 不只改 AB 三條 route，還改 **六條 CtrlRAM AB bank Replace route** 的複合定義與 fingerprint；A-01／A-02 另穿透 General Merge 候選 bundle 與其 saved-rule parent。有三件事在 1.2.1 不能閉合，列為 1.2.5 前提（第 7 節）：並行 preload 的 runtime 依賴圖保證（owner 於 Q7 選擇非建置 trust index 也並行，故為 **R3 前提**）、comparer 完整性的機械證明、bank Replace 的 Golden／write-range 證據等級（Q8 已定遷移 gate，接受邊界由 firmware-owner 記錄）。owner 已以 decision 235 答覆 Q1–Q8（owner 答覆表）。字面 `ref`／`recipeReference` 今日在 trusted gateway 被兩份 schema 的頂層 `additionalProperties: false` 拒絕（`composition-profile-v2.17.schema.json:6`；`firmware-family-v1.3-full-image-metadata.schema.json:6`；`ProfileBundleLoader.cs:139`），在 owner 核准語法並以 trust index 選入新 schema 之前不是功能。

### 5.4 資料流：S1 → trusted 原始 snapshot → S1′ 展開＋重驗 → DTO → normalizer（修正 N4）

為何不能「替換 DTO 後跑既有 normalizer」：v2.17 有 12 條頂層 `allOf`（`composition-profile-v2.17.schema.json:167-1252`），如 `declared-prefix-with-warning` ⇒ `compositionKind: merge`（`:169-210`）、`compilationContext.kind` ⇒ `operations`／`views` 形狀（`:211-247`）、`pad-shorter` ⇒ replace＋`dp-replace`＋無 processorStages（`:956-1001`）、`ab-merge` 與否決定 `output` 形狀（`:1209-1234`）。normalizer 不接 `experience` 判 output（`CompositionProfileNormalizer.Output.cs:8-11,17,34`）；Domain 對 pad 只檢查 Replace 且無 processor（`CompositionProfileDefinition.Graph.cs:222-235`）。recipe 與 consumer 各自合法不代表合成後合法。

契約（一條資料流，JSON 展開）：

1. **S1**（不變）：來源文件各自通過其 bundle 選定 schema（`ProfileBundleLoader.cs:139`）；帶 `recipeReference`／`regionSetReference` 的文件以新 successor 的引用分支驗證；`TrustedProfileBundle` 仍持有**原始** snapshot（`:146`）。pre-built 模式照 ADR 0077 省略此評估。
2. **S1′**（新，在 `CreateDocumentProjection` → `TrustedProfileBundleDocumentProjection` 內、`ValidateAndClone` 之前）：
   - recipe：取同 manifest 目標 entry，比 `contentHash`，檢 kind 相容，把 9 區塊併入 consumer `JsonElement`、移除 `recipeReference`；
   - regionSet：經 trust index provider 找 provider bundle，取其**已准入文件**（`TrustedProfileBundle`／accepted catalog 的 snapshot，不是 catalog）中 id＋version＋hash 相符的 family，取 `regionSetId` 相符的 inline 項目，併入 consumer family JSON；
   - **展開後的完整 `JsonElement` 以 consumer 選定 schema 的 inline 分支，經同一個 `ProfileBundleSchemaValidator` 的 `JsonElement` 評估 seam（`:151-165`）重新驗證**；失敗＝S1′ 拒絕（`InvalidDataException`＋path，同 S1 型）；
   - `ValidateAndClone` 需新增接受合成 `JsonElement` 的入口（今日只讀原始 snapshot，`TrustedProfileBundleDocumentProjection.cs:155-175`）→ DTO → Profiles normalizer → Domain，三者不改。
3. 守衛改寫：`ProfileSchemaTrust.cs:40-75` 保留「S1 先於 `new TrustedProfileBundle(`」，新增「S1′ 的 schema 重驗必須先於任何展開內容的 DTO／normalization 消費」；projection 是唯一展開點。
4. JSON／pre-built 兩路：展開本身兩路都在 runtime 執行（DTO 需要它）。合成文件的 schema 評估：JSON 路徑 runtime 執行；pre-built 路徑若要省略，需 generator 在建置期執行 `CreateDocumentProjection`（ADR 0077 `:193-198`）並把合成文件評估納入 build admission identity 的 soundness 論證（`:263-273`）——這是 ADR 0077 的 amendment（R3 trust policy），列為 1.2.5 前提（第 7 節）；否則 runtime 一律評估，代價是 schema parse 成本。
5. S1′ 不新寫平行驗證規則，只做 hash／kind／目標存在／深度檢查與 JSON 合成；形狀全部交 schema。展開結果是 ephemeral 投影，不序列化、不當 identity；`V2CompilationProvenance` 可增「已解析引用」id＋hash 清單（只增身分，ADR 0046 `:118-128`），非必要。

### 5.6 等價的定義（修正 N1、N2）

**必變且必須重算、重新 pin**：consumer 文件的 manifest `contentHash`；consumer 內的 pin；bundle `contentHash`；trust index bytes 與兩個 build admission identity；受影響 bundle **全部** route 的 `CapabilityFingerprint`——靜態／dynamic route 傳新 bundle hash（3.2 第 7 點），**bank Replace route 傳重算後的複合 `BankReferenceReplaceDefinition.ContentHash`**（layout 側 bundle／entry／family hash 任一變即變，`RuntimeReferenceBankReplaceV2CompilationContext.cs:95-108`）及其 `bank-definition:` semantic binding（`CanonicalDynamicRouteInventory.Banks.cs:75-77`）；policy pin（`canonical-capability-policy-v1.json`，340 處字串，非 route 數）；`CompilationFingerprint`；pinned `CanonicalCatalogSnapshotDigest`（`CanonicalCatalogSnapshotDigestTests.cs:29-43`）；Golden `routeEvidence[].capabilityFingerprint`（`manifest.json:222-226,804-840`）；`AbMergeGoldenRegressionTests.cs:18-20` 常數；`release_source_pins` 輸出；pack bytes；General 受影響時 saved-rule parent。驗收是「新值等於以新 bytes 重算的值」（`CapabilityDefinitionFingerprint.Compute(...)`；bank Replace 以 `BankReferenceReplaceDefinition` 重算），發布時 `CanonicalCapabilityCatalogSource.cs:147-160` 的相等檢查是 runtime 證明。重算相等只證明一致，不證明語意相同——語意由下列比較證明。

**依 owner 選項額外允許的差異**（修正 N2）：Q5 選 patch bump 時，`familyVersion` 在 consumer pin、trust index provider 條目、`resolved-map.fingerprint` 輸入、digest `composition.context.family-version`（`CanonicalCatalogSnapshotDigest.cs:352`）、`V2CompilationContext.FamilyVersion` 都會變，列入允許差異並以「版本值＝新宣告值」驗證；Q6 選 (a) 時，既有 metadata S2 失敗的 code／訊息變更列為 owner-approved 差異，失敗契約比較以「新舊 code 的對照表」驗證，成功路徑仍須完全相等。

**必不變（執行語意；修正 T1、T2）**：遞迴比較三種 typed contract——`CompiledComposition`（`CompiledComposition.cs:32-84`：`Plan`、`Eligibility`、`V2Details`）、每 member 的 `CompositionProfileDefinition`、bank Replace 的 `RuntimeReferenceBankReplaceV2CompilationContext`（含 `LayoutComposition` 與 `Banks[].LocalComposition` 兩個 parent composition，`RuntimeReferenceBankReplaceV2CompilationContext.cs:162,196,203`，遞迴套用同一表）。不用全域「忽略所有 hash／version」規則，而是一份 **identity 轉換表**：表內每個位置的新值必須等於對應的新宣告或重算值；表外全部成員逐項相等。

### 5.8 循環、深度、layer 與並行（修正 N3、F6）

- 跨 bundle 載入 DAG 與同 bundle 文件引用圖分開：recipe（選項 A）由 schema 構造為深度 1；選項 B 在 S1′ 檢查 donor；regionSet 的 provider 目標必須 inline（S1′ `reference-depth-exceeded`）；metadata 既有深度 2 鏈不重開。on-demand consumer（GM candidates）只能是 consumer（`MatchesTrustIndex` 要求 excluded bundle 無 provider 宣告，`BuiltInV2BundlePreload.cs:112-125`），其引用在開啟時由 S1′ 解析，不進 preload 表。
