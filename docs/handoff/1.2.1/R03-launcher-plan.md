D7's “old Catalog” specifically means its bytes/hash, schema, or latest version mismatches the current Registry publication assertion, not an invented Catalog revision of its own. ADR 0053 :99–104 governs Registry revision; ADR 0066 :151–157 explicitly states direct/manual-pinned roots have no persistent schema floor and owner may explicitly select an old Catalog schema through a higher Registry revision. A1 must accept or reject this limitation; Case A cannot claim resistance to an attacker already controlling ACL/publisher and publishing a higher revision. Nor can first acceptance, without durable high-water, claim a historical replay baseline; acceptance uses a client that has durably accepted a higher revision. 〔E33〕

Entry negative cases must distinguish at least `Busy→Busy(12)`, `Damaged→RecoveryRequired(11)`, `StartFailed→LaunchFailed(14)`, `Unavailable→HealthUnavailable(13)`, and invalid handoff shape→`TerminationUnconfirmed(17)`. This is a typed/MapExitCode mapping; the Setup/Recovery UI path ultimately returns through `App.ConfigureAndRun`, so the mapping must not be treated as the final process exit in every scenario. 〔E27〕
If signatures/HTTPS/delta are adopted, the corresponding F14/F18/F19 or F12/F13 become necessary: add fallback preserving the same trust, signature/replay/revocation/expiry/rotation negative cases, or complete ZIP and installed-byte equality for full/cold/warm delta. Adding features without their fault gates is not allowed.
