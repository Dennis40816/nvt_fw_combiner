## 量的算法

- 規模權重 S=1、M=2、L=4，沿用 inventory 的 S/M/L。這是相對工作量，不是日數。
- R3 的 L 項目 gate 成本較高。因此以 R3 為主的版本，權重刻意壓在 28–30。

## 分配原則

1. **1.2.1 只做盤點、契約與方向決定**（R0/R2，外加一項 R3 事實盤點）。之後每個實作版本都以 1.2.1 定下的契約為起點。
2. **每版一個主題、一條主要 authority 鏈。** R3 集中在四個版本：
   - 1.2.2 parity/release；
   - 1.2.5 firmware；
   - 1.2.6 release/publisher；
   - 1.2.11 CI governance。
   UI 版本不帶 R3。
3. **每版權重約 25–38**，平均約 31。
4. **先做能保護或加速後續的工作：**
   - P-2 比較器排在 1.2.2。後面的大檔和 Combiner 取代等 firmware 變更就有前版比較可用，之後的 release 也不必再豁免 ADR 0078。
   - CLI/Desktop 自動化與 T3 測試選擇排在 UI 大批工作之前。roadmap 1.2.3 原文也要求這個順序。
   - T4a shadow 證據窗從 1.2.3 開始，累積到 1.2.10，1.2.11 才啟用 T4b。
5. **每個依賴都指向同版或更早的版本**；文件總對齊放最後。
