## Identity

- **Purpose**: this board records the owner decisions of the `1.3.x` line, the handoff order of its work, and each
  item's branch, base and internal tag. It does not own product behavior (`SPEC.md`, ADRs, contracts), the version
  rules ([roadmap](../architecture/nfc_roadmap.md#owner-version-line-decision--2026-10-07)) or completed history
  (`CHANGELOG.md`). Customer version numbers are chosen at release, not here.
- **Trunk `1.3.x`**: created from the `1.2.x` tip `6b3390e72`. After the `1.3.0` release branch was cut, it takes
  feature pull requests and Core adoption pull requests in the handoff order below.
- **Release branch `1.3.0`**: cut from `1.3.x` at `6b3390e72` on 2026-10-07. It takes only the items listed for
  `1.3.0` and release fixes. Each merge into `1.3.0` is merged back into `1.3.x`.
- **Line `1.2.x`**: Core-free hotfixes only. The release branch `1.2.2` is cut from `v1.2.1`. A later hotfix is cut
  from the previous release tag.
- `feature/1.3.1/core-integration` is retired (decision 335). Its removal goes to the owner as a list first
  (decision 320).

## Open owner questions

- **OQ-1, Bootstrap trust anchor.** A managed update never replaces the Root Bootstrap (ADR 0056), and
  `release-manifest-v1.md` lets only a Bootstrap from the first two-value release start a `LicenseRef-Proprietary`
  release. `1.2.2` does not contain license bridge step 1 (decision 332). An installation made from `1.2.2` therefore
  cannot start the first Core release by updating to `1.3.0` alone. Until the owner decides, UPD-BRIDGE assumes the
  contract's rule: such an installation needs a reinstall from the `1.3.0` distribution, unless a separately approved
  Bootstrap migration is added.
- **OQ-2, comparator source.** A formal comparison report must run from the exact release source.
  `scripts/predecessor_rolling.py` compares the candidate commit's comparator files with the running ones and reports
  `SOURCE_MISMATCH` when they differ. A `1.2.2` report run from `1.3.0` tooling (decision 337) therefore cannot be a
  report of record. Until the owner decides, the recommended path is to merge the comparator tooling, which has no
  Core, into `1.2.2` itself. CMP-TOOL then targets `1.2.2` instead of `1.3.0` and merges forward.
