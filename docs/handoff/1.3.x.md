# 1.3.x board

Writer: Claude Code (commander). Workers update only their own workstream
logs on their own branches. Protocol: [handoff README](README.md).

Last updated: 2026-10-07. This board continues the open work of the
[`1.2.x` board](1.2.x.md). Decision numbers continue that board's sequence, which ends at 331.

## Identity

- **Purpose**: this board records the owner decisions of the `1.3.x` line, the handoff order of its work, and each
  item's branch, base and internal tag. It does not own product behavior (`SPEC.md`, ADRs, contracts), the version
  rules ([roadmap](../architecture/nfc_roadmap.md#owner-version-line-decision--2026-10-07)) or completed history
  (`CHANGELOG.md`). Customer version numbers are chosen at release, not here.
- **Trunk `1.3.x`**: created from the `1.2.x` tip `6b3390e72`. After the `1.3.0` release branch was cut, it takes
  feature pull requests and Core adoption pull requests in the handoff order below.
- **Release branch `1.3.0`**: cut from `1.3.x` at `6b3390e72` on 2026-10-07. It takes only the items listed for
  `1.3.0` and release fixes. Each merge into `1.3.0` is merged back into `1.3.x`.
- **Line `1.2.x`**: Core-free hotfixes only, until `v1.3.0` is published. The release branch `1.2.2` is cut from
  `v1.2.1`. A hotfix before `v1.3.0` is cut from the previous release tag. After `v1.3.0` is published, a Core-free
  fix takes the next contiguous `1.3.x` customer version instead (decision 336), and no further `1.2.x` is released.
- `feature/1.3.1/core-integration` is retired (decision 335). Its removal goes to the owner as a list first
  (decision 320).

## Internal tags

Decision 341 sets one internal tag per handoff group.

- Name: an annotated SemVer prerelease tag, as [development tags](../governance/development-tags.md) requires. The
  exact name is chosen when group 1 completes and is recorded here.
- The tag is an annotated tag on the trunk merge commit that completes the group. It never gets a Release, and the
  Launcher never offers it. A tag never moves.

## Handoff order on the 1.3.x trunk

The owner's words in decision 318, 「可以先用各自的，但路徑未來要統一」, let each line keep its own status table for now.
This board is the status table of the `1.3.x` line, one status home per item. The
[`1.2.x` status ledger](1.2.x-status-2026-10-05.md) stays the status table only for items that this board does not list,
and nobody updates a ledger row for an item that this board lists.

The order follows decision 335 and the Commander's draft of 2026-10-07. `NN` is the position in the order. Status
values: done, in review, in progress, not started. The first customer release after `1.3.0` takes whatever is done in this order, and it must
contain LIC2, UPD-BRIDGE and MIGRATE if it contains any Core. LIC2 and the first Core adoption pull request (#581)
merge back to back: no customer release is cut from a trunk head that has LIC2 without Core. Items 01 to 06 form one
release boundary: from the merge of LIC2 until UPD-BRIDGE and MIGRATE have merged, no customer release is cut from
the trunk. A release fix in that window goes on a new exact-version branch cut from the latest published tag, with the next
contiguous customer number, as `1.2.2` was cut from `v1.2.1`. After publication its `main` merge commit merges back into `1.3.x`, as BACK-12x does.

## Merge-back of 1.2.2

`1.2.2` and `1.3.0` both change profile pins and test counts. Measure the conflicts on the actual heads when the
merge-back pull request is opened, then recompute the pinned hashes and counts and run the full suite.
