# ADR 0065: Exact managed Setup recovery execution

Status: Accepted for `RECOVERY-105B`

Extends: ADR 0063 and the managed Setup v1 contract only for one explicitly
invoked, restart-safe convergence or rollback of an exact interrupted Setup
transaction. ADR 0062 remains the Setup producer and marker-schema owner.

## Context

ADR 0063 supplies a complete read-only diagnosis. It intentionally cannot
acquire the version-manager writer lease, delete durable state, mutate a Setup
tree, or remove a marker. A surviving `bootstrap-launch-recorded` marker can,
however, coexist with state written by Bootstrap before READY. Deleting only
the managed root and marker would leave stale Application or Launcher state
that permanently blocks the next Setup attempt.

The release owner selected Option A on 2026-08-30: the explicit **Remove
incomplete installation** action may remove the exact Application and Launcher
state generated by that same incomplete transaction. This is not general state
reset, uninstall, directory adoption, or repair authority.

Recovery must also survive termination during deletion without adding a new
marker phase or recovery journal. Therefore a restart may accept only a prefix
of one deterministic deletion order, never an arbitrary set of missing paths.

## Decision

Application retains one pure recovery-policy owner but exposes two
least-authority coordinators. Read-only `ManagedInstallationRecoveryExperience`
produces an immutable plan and exposes the selected action from read-only
ports. `ManagedSetupRecoveryExecutionCoordinator` accepts that plan, acquires and
holds the canonical `IVersionManagerStateStore` writer lease, re-observes every
fact through the same policy, and executes either READY convergence or
incomplete-transaction rollback. Diagnosis never requires a state writer or
mutation port merely to read health.

Infrastructure implements one narrow execution port. It may compare the
supplied expected token with exact no-follow held identities and perform only
the selected deletes. It does not acquire another writer lease, classify a
state pair, choose an action, start a process, or replan.

### Closed first-run state-pair policy

[`managed-recovery-v1.md`](../contracts/managed-recovery-v1.md) is the sole
executable owner of the state-pair table, evidence requirements, fixed delete
order, restart-prefix rule, and terminal-outcome mapping. In particular,
Missing/Missing during `staging` is actionable only when the evidence adapter
can prove the exact deterministic tree inventory/restart prefix. An ordinary
partial extraction is preserved for manual intervention.

### Immutable plan and revalidation

An actionable diagnosis carries one opaque execution token that binds:

- the complete exact Setup transaction and marker bytes;
- normalized state, root, marker, and staging identities;
- the candidate admission and verified Launcher identity for every complete
  installed-tree observation; after the fixed deletion sequence has begun, a
  proof-gated Missing/Missing marker-derived restart prefix may instead carry
  explicit Launcher-identity absence, including retained-manifest and terminal
  skeleton prefixes where the Launcher is no longer independently verifiable;
- exact Application and Launcher state snapshots or exact absence;
- the closed root/staging inventory proof;
- the deterministic deletion sequence; and
- Bootstrap, Application, and Launcher lifetime roles observed as terminal.

The opaque Infrastructure token binds only exact filesystem evidence.
Application's immutable internal execution request is the sole boundary that
binds that token to the policy-selected action; Infrastructure does not infer
or reconstruct that choice.

Execution first acquires the canonical state-path writer lease in Application.
While retaining it, Application passes that same live non-serializable lease
result to Infrastructure, observes all three lifetimes again, reloads
state/root/marker and the state-pair policy, and rejects any token drift. The
adapter verifies the live result still owns the exact state path; disposed,
foreign-path, or arbitrary-disposable results fail closed. Infrastructure then
opens the exact marker and authorized targets without following reparse points,
repeats identity/topology/token comparison, and only then mutates. The closed
outcome mapping is owned by `managed-recovery-v1`.

The adapter's completion claim is intentionally limited to the canonical
writer-lease observation window: held delete is followed by two exact-missing
observations through the stable no-follow ancestor chain before return. An
external writer can create a new foreign residue only after that boundary; the
next health observation must reject it. This ADR does not introduce the
journal, ACL, or exclusive parent custody that a permanent-absence guarantee
would require.

### READY convergence

READY convergence retains both durable state files and the complete managed
root. It may remove only the exact transaction staging child/container when it
is verified empty, followed by the exact schema- and identity-matched marker.
The marker is last. It never starts Bootstrap again.

### Rollback order and restart

The exact global order, proof retention, cancellation boundary, and only
accepted restart prefixes are normative in `managed-recovery-v1`. The key ADR
constraint is unchanged: the marker is last, no arbitrary missing subset is
normalized into progress, and no new journal or marker phase is introduced.

## Outcomes and non-goals

Execution uses only the closed typed outcomes and one-to-one mappings in
`managed-recovery-v1`. Presentation does not infer an outcome from paths,
exceptions, or partial UI state.

This slice does not add a recovery journal or Setup phase/schema. It does not
download or select a source; restart Bootstrap; repair a package, shortcut, or
state; rebind or move a root; migrate 1.0.x; uninstall a healthy installation;
or alter firmware bytes, profiles, ranges, CRC, naming, support, or golden
evidence.

## Consequences and verification

- Application retains the unique first-run policy; its diagnosis and executor
  coordinators preserve separate read-only and writer authority. Infrastructure
  retains filesystem/JSON/held-handle mechanics.
- Setup remains the sole marker writer. Recovery can only delete the unchanged
  marker after exact revalidation.
- Tests cover the full state-pair table, immutable-token drift, writer
  contention, all lifetime roles, every marker phase, READY convergence,
  fixed-order crash injection before/after every deletion, restart prefixes,
  holes, foreign paths, reparse/replacement races, and zero Bootstrap starts.
- This is R3 destructive release/security work. Completion requires an
  independent exact-head architecture/security/evidence review, the canonical
  full gate, and release-owner exact-head attestation.

## Rejected options

- Keeping stale state while deleting the root and claiming Setup can restart.
- Background cleanup or a second confirmation modal.
- Infrastructure-owned state-pair classification or a second writer lease.
- Generic recursive path deletion, arbitrary missing-subset acceptance, or
  using the ordinary managed-version delete path.
- A new recovery journal or Setup marker schema merely for exact residue.
- Calling Bootstrap again to discover whether READY occurred.
