# v1.1.x AB IC selector scope handoff

Status: owner-requested `v1.1.x` selector correction; exact release unallocated.

The owner observed that switching the Merge page to AB Code leaves the IC
drop-down showing the broader Merge-page IC list. This handoff records the
root cause and the smallest later correction. It is excluded from `v1.1.1` and
changes no profile admission, topology, input slot, firmware range, operation,
output byte, naming, or release content.

## Reuse inventory and root cause

The canonical AB authoring policy is already present and must remain the only
authority for the selector contents.

- `CapabilitySelectorPublication.Create` derives workflow-authorable ICs from
  one exact canonical catalog publication. `IsWorkflowAuthorable` and
  `WorkflowSelectorProjection.WorkflowIcChoices` already produce the AB-only
  list; the current built-in publication yields `NT51919`, `NT51929`,
  `NT51932`, `NT51950`, and `NT51951`.
- `WorkflowSessionPresentationViewModel.IcChoices` already selects that
  workflow-scoped projection when the Merge page and AB Code mode are active.
  Before the mode switch it correctly returns the broader Merge-page union.
- The live binding becomes stale during an in-page mode switch. After
  `MergePresentationViewModel.SelectMergeMode` accepts AB Code,
  `PublishAcceptedMergeSharedContext` records the mode and refreshes shared
  text but does not publish `IcChoices`. The bound IC `ComboBox.ItemsSource`
  therefore retains the collection obtained while Standard Merge was active,
  even though a direct read of the getter now returns the narrower AB list.
- This suppression is intentional debt rather than a catalog defect:
  `ModeSelectorBindingTests.FirstMergeModeSelectionAfterPageEntryRemainsSelected`
  currently asserts that `IcChoices` is not raised during the selector event so
  replacing the choices cannot re-enter the two-way mode selection and reject
  the user's first click.
- `PublishCanonicalCatalogIcChoices` is the existing guarded owner for a live
  IC `ItemsSource` refresh. Its `_isPublishingCanonicalCatalogChoices` guard
  and the `SelectedIc` blank-selection guard already preserve a still-valid
  selection during canonical catalog replacement; the AB correction must reuse
  this owner rather than duplicate raw notification logic.

The correction must therefore reuse the existing canonical publication,
workflow projection, selected-page context, and mode-selection transaction. It
must not hard-code IC identifiers in XAML, add an AB-only catalog, infer support
from filenames or firmware metadata, or change profile promotion to repair a
Presentation publication bug.

## Intended selector contract

1. Once AB Code mode selection is committed, the visible IC drop-down contains
   exactly the ICs for which the same canonical publication reports
   `IsWorkflowAuthorable(ic, ExperienceIds.AbMerge)` in publication order.
2. The accepted mode and current IC are retained when that IC remains in the
   AB projection. A catalog refresh that removes the route uses the existing
   fail-closed workflow/catalog reconciliation; an unsupported IC is never
   retained merely to keep a visual selection.
3. Returning to Standard Merge republishes the existing Merge-page IC union.
   Leaving Merge continues to restore the destination page's own projection.
4. After `_selectedMergeMode` has been assigned,
   `PublishAcceptedMergeSharedContext` synchronously republishes `IcChoices`
   exactly once through the existing guarded `PublishCanonicalCatalogIcChoices`
   path. The still-authorable current IC is retained. The correction must not
   add a dispatcher, timer, arbitrary delay, second selector state, or a second
   publication helper.
5. The IC selector's label, keyboard order, focus, selected-value announcement,
   detail disclosure, and Number/topology behavior remain unchanged. NT51950
   alone retains its profile-owned `1 IC`/`Cascade` choices; selector filtering
   does not infer topology.

## Composition boundary

- Composition kind remains `merge`; experience remains `ab-merge`; audience
  remains `system`; layout and input policies remain `fixed`.
- Output initialization remains the profile-owned blank image followed by the
  declared DP_AB/TPA/TPB operations. The fixed input slots remain DP_AB, TPA,
  and TPB.
- Authorability comes only from the current canonical capability publication.
  Promotion blockers and support/certification claims remain unchanged.
- No memory map, address space, region access rule, processor, integrity,
  validation, output naming, or firmware access policy changes.

## Acceptance outline for the allocated release

- A production-bound headless test starts on Standard Merge, selects AB Code
  through the real mode `ComboBox`, completes normal Avalonia binding delivery,
  and asserts that AB remains selected, the mode `ComboBox.ItemsSource`
  identity is unchanged, the actual IC `ComboBox.ItemsSource` synchronously
  becomes the canonical AB workflow projection, and the compatible current IC
  and focus are preserved.
- The same binding test switches back to Standard Merge and asserts that the
  actual IC `ItemsSource` returns to the canonical Merge-page projection. It
  proves exactly one `IcChoices` publication per accepted transition and no
  first-click rollback or mode-selection loop. The existing first-click test
  changes its inverse `IcChoices` assertion to this exactly-once contract while
  retaining every mode-selection assertion.
- A negative projection fixture includes an IC that is authorable for Standard
  Merge but not AB Merge and proves it is present in the page union yet absent
  from the AB selector. No test hard-codes a second product support matrix.
- Catalog-refresh coverage proves the selector is derived from one resolution
  token, preserves a still-authorable selection, and uses the existing
  fail-closed reconciliation when the selected AB route disappears.
- Existing Home AB context, AB topology, page-navigation, retained-input,
  accessibility, and canonical-catalog refresh tests remain green.

## Version boundary

release and grants no implementation authority.
