# v1.1.x AB DP metadata layout handoff

Status: handoff-only scope, acceptance, diagnosis, and evidence. Version
allocation and completion status are owned by the [NFC roadmap `v1.1.8` milestone](../architecture/nfc_roadmap.md#118-ab-selector-and-dp-metadata-layout).

The owner-provided AB Code Merge screenshot shows both DP bank project values
truncated while the right half of the facts region remains unused. This handoff
records the later UI correction only. It is excluded from `v1.1.1` and changes
no input decoding, firmware range, route, output byte, naming, or release
content.

## Reuse inventory and exact diagnosis

The screenshot symptom has two coupled Presentation causes; it is not evidence
that the underlying DP observations have lost their structure.

- Application already owns independent typed `Major`, `Minor`, and `TrackerId`
  values in `CompiledInputVersionObservation`. That contract remains unchanged.
- `FirmwareInspectionProjection.ApplyAbInputFacts` already owns the AB slot
  projection, but `FormatAbVersion` currently concatenates one bank's version
  and tracker into a single value such as `D06-00 · AUTO_PRJ-4095`.
- The shared `FirmwareSlotCard` deliberately uses the existing
  `FirmwareSlotInformationFactTemplate` in a four-column desktop `UniformGrid`
  and a two-column compact layout below its 820-pixel card breakpoint. Because
  DP_AB currently contributes only two combined facts, they occupy the first
  two quarter-width cells while the remaining two cells are empty. The shared
  fact template then correctly ellipsizes each combined value inside its own
  narrow cell. This explains the apparent unused width in the screenshot.
- Ordinary DP projection in `UiCompositionRunner.GetDpFirmwareSlotFacts`
  already presents DP Version and Jira Index as separate
  `FirmwareSlotFactViewModel` values. AB must reuse that fact model, template,
  tooltip, trimming, and responsive host; it does not need a new bank-group
  component, layout engine, or metadata model.

## Intended interaction and layout contract

1. A known DP_AB input is projected in this deterministic logical and visual
   order: **DP1 Version**, optional **DP1 Jira Index**, **DP2 Version**, optional
   **DP2 Jira Index**. Version values remain invariant `Dxx-xx`; Jira Index
   values remain invariant `AUTO_PRJ-n`. The middle dot is no longer used as
   semantic structure.
2. When both Jira Index values exist, the four independent facts fill the
   existing four desktop columns. In the existing two-column compact layout,
   DP1 Version/Jira Index form the first row and DP2 Version/Jira Index form the
   second row. No generic `FirmwareSlotCard` geometry is redesigned solely for
   AB, and no fixed two-bank row claim is made when an optional Jira fact is
   absent.
3. A missing tracker, including a decoded tracker value of zero, follows the
   existing Standard DP policy and omits that bank's Jira Index fact instead of
   fabricating a Not applicable placeholder. An unknown bank retains a
   localized Unknown Version fact and exposes no Jira Index fact.
4. Unknown help text is localized through `ShellTextResources`. `DP1`, `DP2`,
   `Version`, `Jira Index`, `Dxx-xx`, and `AUTO_PRJ-n` remain invariant
   technical vocabulary shared with Standard DP; AB does not introduce a new
   `Project` label.
5. Each value retains the shared independent character ellipsis and exact-value
   tooltip. Assistive reading order exposes the rendered label/value pairs in
   the same DP1-then-DP2 order; if the current fact container cannot expose
   those pairs, the smallest shared repair binds its existing
   `StateAutomationText` rather than adding an AB-specific automation model.
6. The selected filename/reveal action, Verified state, Browse/Clear actions,
   desktop card height, identity/action geometry, spacing tokens, minimum
   height, keyboard order, selection/admission, latest-generation inspection,
   and all firmware semantics remain unchanged. Compact height may grow only by
   the existing second fact row; no new wrapper, padding, or breakpoint is
   introduced.

## Acceptance outline for the allocated release

- A projection test with long valid trackers such as `AUTO_PRJ-4095` asserts
  four ordered Version/Jira Index facts with exact independent values and no
  value containing ` · `. `FormatAbVersion` is removed when it has no remaining
  caller; it is not replaced by another concatenation helper.
- Missing-tracker and unknown-bank cases assert that Jira Index is omitted,
  Version remains in DP1-then-DP2 order, and unknown Version help is localized
  in English and Traditional Chinese.
- A rendered production `FirmwareSlotCard` regression first reproduces the
  owner screenshot geometry. At that owner screenshot/approved desktop width,
  all four values, including `AUTO_PRJ-4095`, render without ellipsis and the
  DP2 Jira Index cell occupies the rightmost column. At narrower widths each
  field may trim only within its own cell and exposes the exact value through
  the shared tooltip. In the both-tracker compact fixture, row 1 is DP1
  Version/Jira Index and row 2 is DP2 Version/Jira Index.
- Long-filename coverage proves filename ellipsis/tooltip, Verified, Browse,
  Clear, focus order, and action geometry are unchanged in both themes and both
  languages.
- Accessibility coverage verifies the rendered label/value pairs and
  deterministic reading order. Existing AB inspection/admission and shared selector
  four-/two-column regressions remain green.
