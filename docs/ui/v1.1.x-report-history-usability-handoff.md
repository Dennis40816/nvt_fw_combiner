# v1.1.x Report History usability handoff

Status: Raw-copy, History actions, and approved Run reports list/Load-report relocation locally implemented and verified. Version
allocation is owned by the [NFC roadmap `v1.1.4` milestone](../architecture/nfc_roadmap.md#114-ui-corrections-and-ab-dummy-dp).

This handoff records four owner-observed Report History problems: a single
entry cannot be deleted in the running UI, the delete affordance should match
the selector trash-can treatment, a history card cannot open its individual
report with one click, and the Raw report region lacks a top-right copy action.
It also records the owner direction to move the existing global **Load report**
entry into the Report experience instead of leaving it as an unrelated shell
utility.
It is excluded from `v1.1.1` and changes no report schema, firmware behavior,
output bytes, history capacity, or evidence semantics.

## Reuse inventory and confirmed diagnosis

Most behavior already exists. This work begins with a red UI reproduction and
repairs the existing path; it must not add a second history store, report
projector, navigation service, or clipboard abstraction.

- `ReportPresentationViewModel` already owns
  `OpenReportHistoryEntryAsyncCommand` and
  `RemoveReportHistoryEntryCommand`. Direct ViewModel tests prove both command
  bodies, cancellation, projection-generation safety, and collection updates.
- `ReportHistoryFileStore` and the existing queued persistence writer already
  persist the exported bounded collection whenever `ReportHistoryCount`
  changes. Single deletion must continue through this owner and survive a
  flush/reload; it must not edit the JSON file directly from XAML or code-behind.
- `MainWindowReportHistoryTemplates.axaml` already renders the complete history
  card as a button and renders a separate delete button. The confirmed cause
  of both owner-observed failures was the ancestor binding:
  the template looked for the commands directly on
  `$parent[Window].DataContext`, while the commands are owned by that window
  ViewModel's `Reports` child. The original native buttons were disabled;
  corrected real-control and native-click evidence is recorded below.
- `FirmwareSlotCard.axaml` already owns the requested selector delete visual:
  `semanticAction iconButton danger slotClearAction` with the Segoe Fluent
  trash glyph `E74D`, including pointer, focus, disabled, tooltip, and
  accessible-name treatment. Report History should reuse that visual language
  rather than retain its current text `×` affordance. If the style name is made
  shared, the existing selector must retain identical rendered behavior.
- Before this change, `ReportCodeBlockView` demonstrated the compact top-right copy icon,
  `TopLevel` clipboard acquisition, and keyboard-accessible tooltip pattern.
  Its original `async void` handler did not catch a failing `SetTextAsync`, so
  it was visual/acquisition reuse evidence, not failure-safety evidence.
  Before the Raw action reuses that path, a red clipboard-failure control test
  must drive one bounded repair of the existing owner (or the smallest shared
  handler) without adding a clipboard service or package. The Raw report tab
  originally used only a `readOnlyRaw` `TextBox` bound to `LoadedReportJson`;
  the action must keep the large raw viewport and text selection intact.
  The completed bounded repair and its evidence are recorded below.
- Before this relocation, `MainWindow.axaml` exposed Load report in the global utility row,
  and `MainWindow.Report.cs::LoadReportJsonButton_OnClick` already owns the
  native single-JSON picker, 10 MiB bounded read, cancellation, and
  `Reports.LoadReportFileAsync` publication. Relocation must invoke this one
  host flow; it must not copy the picker/read/materialization code into a new
  report loader.

## Intended interaction contract

1. Clicking anywhere on one history card once opens that exact report detail.
   Enter/Space on the focused card performs the same action, and one in-flight
   projection remains cancellable and latest-generation-wins.
2. The adjacent trash-can button first asks for confirmation, identifying the
   exact entry. Cancel is initially focused; Cancel/Escape preserve the entry
   and restore focus. A red Delete action removes only that entry. It must not also
   activate the card, delete the loaded report, clear all history, or change
   another entry. The removal is queued through existing persistence and is
   absent after relaunch.
3. The delete button matches the selector trash-can glyph, dimensions, danger
   color, hover/focus/disabled states, tooltip, and accessible name. The report
   title or sequence is required in its accessible name so multiple trash
   buttons are distinguishable to assistive technology.
4. The Raw report tab exposes one copy button **inside the Raw JSON text box**
   at its top-right, not in the heading/description strip above it.
   One activation copies the complete exact `LoadedReportJson`, not the
   visible/selected subset or a reserialized projection. The raw text remains
   selectable and scrollable.
5. Clipboard unavailability or failure must not crash or close the report.
   The label is localized as raw-report copy, not the existing command-evidence
   wording. A failing `SetTextAsync` regression must cover both the repaired
   existing code-block path and the Raw action.
6. The latest owner-approved reference places Load Report only at the top-right
   of Run reports. Replace its Open report/History landing cards with the direct
   newest-execution-first list. Detail has an explicit back-to-Run-reports action;
   it does not add another Load button. Reuse latest-generation-wins publication.
7. The shell-level Load report utility is removed only after an empty Report
   experience remains reachable when there is no current report and no
   history. If the current modal cannot be opened empty, the same single host
   action must first be exposed from the always-reachable Run Reports hub or
   its empty state; otherwise relocating the button would make first import
   impossible. The approved list reference below now fixes placement, text/icon,
   centered capped columns, overflow-only tooltips and red confirmed deletion.
8. Cancel or a load failure returns keyboard focus to the invoking Load report
   action and preserves the current report/history mode. A successful first
   import from the empty hub opens Report and moves focus to the opened report
   heading or the existing modal focus target; focus must never remain on a
   closed or hidden Message Center control.
