# 0.1.1 UI Interface Planning Scope

`0.1.1` started as the first UI planning milestone after dev0 contract stabilization. The UI is now moving toward a production-backed shell: firmware semantics stay out of XAML and ViewModels, while IC choices, Number choices, profile status, flash-map regions, reports, and build readiness come from application/profile catalogs or application service results.

## Goals

- Confirm the initial desktop navigation model.
- Build a UI that can show profiles, slot-card inputs, visual-first shared Memory coverage, preview, logs, and reports using production catalogs/services.
- Keep UI backed by typed application view models and production application data sources.
- Avoid copying merge/replace rules into XAML or ViewModel handlers.
- Establish bilingual English/Chinese-ready text structure with English as the initial default language.
- Reflect the current implementation priority: normal Merge and normal Replace for DP Replace and CtrlRAM Replace workflows first; AB is deferred.

## Selected structure

```text
Home launcher
  Settings
  Replace: DP | CtrlRAM | General
  Merge: Normal | AB Code disabled

Pages
  Context bar: breadcrumb history
  Workflow Device context: IC | Number on Merge and Replace
  Settings
  Replace: primary workspace + inspector
  Merge: primary workspace + inspector
```

The first screen is a clean launcher with exactly three large cards: Settings, Replace, and Merge. A breadcrumb/history bar stays below the header so Settings can grow multiple levels while allowing return to any earlier level. IC and Number are shown only on Merge and Replace pages in a fixed workflow Device context position. IC selects the target IC family/model; Number selects the IC count/variant such as `single`/`cascade` or profile-specific numeric choices. Replace and Merge pages are independent; they may reuse Memory coverage and slot-card components, but the Replace page must not show Merge workflow controls and the Merge page must not show Replace workflow controls.

Buttons are separated by job: top navigation is a low-noise active tab, workflow modes are rounded pill segmented controls, Home quick jumps are command rows, and disabled Preview/Build/Report actions remain light.

Changing IC or Number refreshes the workflow context: available modes, selected profile, slot cards, Memory coverage, validation state, preview tokens, and Build readiness are treated as stale until the page reloads from the new context.

Saved Rules, Reports, and Diagnostics are not top-level pages for the first usable UI. Reports and diagnostics are run-specific secondary surfaces opened from Preview/Build report modals; Settings may expose diagnostics configuration/export. Saved Rules is hidden in the first UI release until the workflow is implemented and reviewed.

## Merge content

- Mode selector: Normal enabled; AB Code visible but disabled for the current implementation phase.
- Shared IC/profile context from the fixed Device context row.
- NT51950 and NT51951 use the confirmed DP Perspective TP overlay range `0xA000..0x36FFF`; golden cases are still required before production promotion.
- Slot cards backed by user-selected file paths and profile-required input slots.
- Visual-first shared Memory coverage before/after visualization in the same layout position used by Replace.
- Right-side inspector for profile, validation, and readiness details.
- Mapping/operation preview table as supporting detail.
- Validation issue list.
- Build button disabled unless application preview/build readiness is valid.

## Replace content

- Persona selector: DP / CtrlRAM / General.
- Shared Number selector from the fixed Device context row before region and processor sections. Two-option profiles use text choices such as `single`/`cascade`; profiles with three or more concrete count choices use numeric selection, with future room for Other/custom exceptions.
- Base reference BIN slot card using user-selected file paths.
- Replaceable region list from `TpFlashMapCatalog`.
- Overlay/mapping table.
- Visual-first shared Memory coverage before/after visualization in the same layout position used by Merge.
- Processor/tool readiness indicator, including post-replace combiner.exe CRC/header readiness when declared.
- Right-side inspector for readiness, validation, and processor/tool details.

## Settings content

- Profile catalog and tool folder settings.
- Strictness/theme options.
- Diagnostics/log/report access and language preference. Default language is English.
- Non-destructive configuration summaries.
- Breadcrumb navigation for future multi-level Settings pages.

## Secondary surfaces

- Saved Rules: hidden until the saved-rule workflow is implemented and reviewed.
- Reports: opened from a preview/build report modal.
- Diagnostics: shown inside the preview/build report modal, with Settings access for configuration/export.
- Logs: read-only, sanitized, and secondary.

## Typography

- General Avalonia UI stack: fonts:Inter#Inter, Microsoft JhengHei UI, Noto Sans CJK TC, Noto Sans TC, Segoe UI.
- English/Latin: Inter.
- Traditional Chinese: Microsoft JhengHei UI on Windows, with Noto Sans CJK TC and Noto Sans TC fallbacks.
- Technical fixed-width text such as addresses, hashes, CRC values, and terminal snippets: Cascadia Mono, then Consolas.

## Non-goals

- ViewModel-level firmware composition.
- ViewModel-level combiner.exe execution.
- Editable profile schema UI.
- Golden regression UI.
- Release packaging UX.

## Exit criteria

- UI design document reviewed.
- Wireframe or XAML shell updated for the clean three-card home launcher and independent Settings/Replace/Merge pages.
- No ViewModel contains firmware copy/replace/CRC semantics.
- IC, Number, flash-map, profile, and report state are sourced from production catalogs/services.
- Terminal/log/report behavior is documented as secondary, not top-level navigation.
- Merge and Replace share a fixed-position visual-first Memory coverage before/after area with table support.
- Merge and Replace use the same left-workspace/right-inspector layout.
- Navigation and workflow mode selectors expose visible active state.
- Button styling is separated into nav, rounded mode-pill segment, command row, action, and disabled action treatments.
- Slot-card input layout is documented for Merge and Replace.
- Shared IC and Number selector position is documented for Merge and Replace; Home and Settings hide workflow context.
- Breadcrumb/history navigation is documented for multi-level Settings.
- Bilingual text-resource architecture is documented.
- First UI hides Saved Rules.
- Default language and font stack are documented.
