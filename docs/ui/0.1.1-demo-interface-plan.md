# 0.1.1 Demo Interface Planning Scope

`0.1.1` is the first UI planning milestone after dev0 contract stabilization. It should not implement firmware semantics in the UI. It should define the first useful demo shape and confirm information architecture.

## Goals

- Confirm the initial desktop navigation model.
- Design a demo UI that can show profiles, slot-card inputs, visual-first shared Memory coverage, preview, logs, and reports without running real firmware parity flows.
- Keep UI backed by typed application view models and sample/synthetic data.
- Avoid copying merge/replace rules into XAML or ViewModel handlers.
- Establish bilingual English/Chinese-ready text structure with English as the initial default language.
- Reflect the current implementation priority: normal Merge and normal Replace for DP Replace and CtrlRAM Replace workflows first; AB is deferred.

## Selected structure

```text
Home launcher
  Settings
  Replace: DP | CtrlRAM | General
  Merge: Normal | AB Code disabled

Pages
  Shared Device context: IC | IC Num | mode
  Settings
  Replace: primary workspace + inspector
  Merge: primary workspace + inspector
```

The first screen is a clean launcher with exactly three large cards: Settings, Replace, and Merge. IC, IC Num, and IC Num mode stay in a fixed shared Device context row below the header on every page. Replace and Merge pages are independent; they may reuse Memory coverage and slot-card components, but the Replace page must not show Merge workflow controls and the Merge page must not show Replace workflow controls.

Buttons are separated by job: top navigation is a low-noise active tab, workflow modes are segmented controls, Home quick jumps are command rows, and disabled Preview/Build/Report actions remain light.

Saved Rules, Reports, and Diagnostics are not top-level pages for the first usable UI. Reports and diagnostics are run-specific secondary surfaces opened from Preview/Build report modals; Settings may expose diagnostics configuration/export. Saved Rules is hidden in the first UI release until the workflow is implemented and reviewed.

## Merge demo content

- Mode selector: Normal enabled; AB Code visible but disabled for the current implementation phase.
- Shared IC/profile context from the fixed Device context row.
- NT51950 and NT51951 are shown as map-pending candidates until owner memory maps are supplied.
- Slot cards using fake/synthetic metadata.
- Visual-first shared Memory coverage before/after visualization in the same layout position used by Replace.
- Right-side inspector for profile, validation, and readiness details.
- Mapping/operation preview table as supporting detail.
- Validation issue list.
- Build button disabled unless synthetic preview is valid.

## Replace demo content

- Persona selector: DP / CtrlRAM / General.
- Shared IC num selector/input from the fixed Device context row before region and processor sections. First UI supports `single` and `cascade`; `numeric` is contract-reserved for future special cases.
- Base reference BIN slot card using fake metadata.
- Replaceable region list.
- Overlay/mapping table.
- Visual-first shared Memory coverage before/after visualization in the same layout position used by Merge.
- Processor/tool readiness indicator, including post-replace combiner.exe CRC/header readiness when declared.
- Right-side inspector for readiness, validation, and processor/tool details.

## Settings demo content

- Profile catalog and tool folder settings.
- Strictness/theme options.
- Diagnostics/log/report access and language preference. Default language is English.
- Non-destructive configuration summaries.

## Secondary surfaces

- Saved Rules: hidden until the saved-rule workflow is implemented and reviewed.
- Reports: opened from a preview/build report modal.
- Diagnostics: shown inside the preview/build report modal, with Settings access for configuration/export.
- Logs: read-only, sanitized, and secondary.

## Typography

- General Avalonia UI stack: fonts:Inter#Inter, Microsoft JhengHei UI, Noto Sans CJK TC, Noto Sans TC, Segoe UI.
- English/Latin: Inter.
- Traditional Chinese: Microsoft JhengHei UI on Windows, with Noto Sans CJK TC and Noto Sans TC fallbacks.
- Technical fixed-width text such as addresses, hashes, CRC values, and terminal snippets: Cascadia Mono, then Consolas.

## Non-goals

- Real firmware composition.
- Real combiner.exe execution.
- Editable profile schema UI.
- Golden regression UI.
- Release packaging UX.

## Exit criteria

- UI design document reviewed.
- Wireframe or XAML shell updated for the clean three-card home launcher and independent Settings/Replace/Merge pages.
- No ViewModel contains firmware copy/replace/CRC semantics.
- Synthetic data provider is clearly separated from production services.
- Terminal/log/report behavior is documented as secondary, not top-level navigation.
- Merge and Replace share a fixed-position visual-first Memory coverage before/after area with table support.
- Merge and Replace use the same left-workspace/right-inspector layout.
- Navigation and workflow mode selectors expose visible active state.
- Button styling is separated into nav, segment, command row, action, and disabled action treatments.
- Slot-card input layout is documented for Merge and Replace.
- Shared IC and IC Num selector/input position is documented for every page.
- Bilingual text-resource architecture is documented.
- First UI hides Saved Rules.
- Default language and font stack are documented.
