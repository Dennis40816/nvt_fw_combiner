## Acceptance outline

### Read-only implementation inventory (2026-09-06)

Existing AB authoring is owned by `AbMergeAuthoringExperience`, canonical
capability/profile compilation by `CanonicalCapabilityCompiler.AbMerge` and
`V2CompositionPlanCompiler`, execution by the shared `CompositionRunService`.
Current profiles require `dp-ab-input` and seed the output from DP. Dummy mode
therefore needs a typed, profile-compiled DP-free input/initializer selection;
it cannot be implemented by disabling Browse, creating a fake DP file or
overwriting the completed output afterward.

### Read-only architecture assessment (2026-09-07)

Independent `ui_runtime_review` recommends reusing the existing optional input
selection group and compiler lowering, not a sibling Dummy map or executor.
The existing schema permits a 0..1 DP selection group; TP remains required.
Initialize the existing output with FF and retain the complete DP seed only
when DP is active. Ordinary mode still requires DP through explicit typed AB
admission; absence of DP must never silently select Dummy mode.

dynamic selection registration/admission to bind AB input selection together
with its real topology/map subset, including separate 950 single/cascade
capacities. Do not fabricate a map suffix or bypass publication. A toggle must
invalidate the old authoring revision/session and its readiness evidence.

owner; verify this compiler seam before implementation. Preserve the existing
TP operations and real pinned Combiner execution for 950/951.

boundaries and full output, ordinary Golden parity, same/independent TP, and
confirmation cancellation/file preservation. This is design evidence only,
not production admission or a claim that these tests have run.
