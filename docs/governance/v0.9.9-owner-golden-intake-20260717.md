## CtrlRAM Replace artifact contract

CtrlRAM Replace must accept either a TP BIN work image or a declared full
FlashCode image. Both forms use the same TP-relative replacement and Legacy
Combiner postbuild semantics. For a full FlashCode base, the host stages only
the owner-approved zero-based TP prefix, reinserts only that audited prefix,
and preserves every byte after it. The exact TP/full-Flash shapes remain
profile/map facts; undeclared lengths fail closed.

The owner intake in this document supplied a TP-oriented three-stage replay:

1. Standard Merge the Initial DP and original TP and compare the complete
   FlashCode with the owner expected output.
2. Apply selected physical CtrlRAM inputs and Legacy Combiner 1.13 to a staged
   copy of the original TP prefix.
3. Standard Merge the same Initial DP and the updated TP, then compare the
   complete final FlashCode with the owner expected output.

The host must not apply TP offsets directly to an unsliced FlashCode artifact.
ADR 0024 supplies the required TP slice/reinsert architecture contract. This
intake establishes evidence only for the shapes and modes explicitly recorded
in its manifests; it does not promote every IC to the new V2 runtime path.

The NT51927 single case replays this three-stage contract. The initial DP/TP
merge is byte-identical to the supplied FlashCode. The updated final output has
zero payload differences; its 24 residual bytes are confined to known Header
CRC and Header Copy CRC fields. The real tool sample independently changes
exactly the selected NF bytes, four firmware-version bytes, and known
Header/Header Copy CRC fields, with no other mutation.
