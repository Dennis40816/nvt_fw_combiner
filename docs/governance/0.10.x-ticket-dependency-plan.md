# 0.10.x Ticket Dependency Plan

Status: owner-approved and published on 2026-07-25.

This document anchors the reviewed GitHub issue inventory for the `0.10.x`
maintainability program so the repository can be reviewed without reconstructing
planning state from GitHub. GitHub issue bodies remain the live execution
records. If an edge changes, update the issue and this table in the same
planning phase.

`ready-for-agent` means that a ticket is sufficiently specified for agent
execution. It does not override a listed blocker, evidence gate, branch rule,
review requirement, or owner approval. A ticket is on the executable frontier
only when every listed blocker is complete and its own intake gates are
satisfied.

Dependency depth is a topological planning aid, not a release number. Tickets
at the same depth may run independently only when they do not contend for the
same files, ownership seam, private evidence, or human reviewer. The owner
allocates dependency-ready tickets to an actual later `0.10.x` release; this
plan does not assign `0.10.1`, `0.10.2`, or any other version.

## Execution frontier at publication

At publication, the dependency-free planning frontier is #170, #171, #172,
and #191. This statement records graph shape only; it does not start those
tickets, allocate worktrees, or assert that their issue-local evidence and
branch intake gates are already satisfied.

## Change control

Any dependency change must preserve all of the following:

1. the issue body and this repository anchor agree;
2. no ticket is moved ahead of its characterization, evidence, or ownership
   prerequisite;
3. a dependency depth change is not presented as an automatic release
   allocation;
4. `ready-for-agent` remains a specification-readiness label rather than a
   bypass for blockers; and
5. the final integration gate remains downstream of coverage, verifier,
   compatibility-owner deletion, and legacy-runtime retirement.
