## Method and inventory

This audit is bidirectional:

1. current authority to production owner and executable evidence; and
2. changed production behavior back to exactly one current authority.

The repository inventory included the root `SPEC.md`, all five documents under
`docs/specs` (including the canonical pointer), 43 numbered ADRs with 40
current or partially current decisions, 45 contract files including 27 JSON
schemas, 25 built-in bundle manifests, 109 built-in composition-profile JSON
documents, 20 built-in firmware-family JSON documents, affected production
code, and test/golden manifests. Superseded or historical material was checked
for an explicit lifecycle boundary rather than treated as current behavior.

Repository structure validation supplies Markdown-link, structured-file,
canonical-golden, policy, packaging, skill, workflow, and contract checks.
Profile-contract and architecture suites supply schema/materialization and
layer/authority checks. Those automated gates support, but do not replace, the
manual changed-authority review below.

## Confirmed deviations and disposition

1. `docs/specs/profile-schema.md` still described V1 as the current production
   loader. It now identifies V1 only as historical migration evidence.
2. `docs/specs/dev0-contract-scope.md` still described itself as a working
   authority. It now has an explicit Historical status and points to current
   owners.
3. The current NT51932 2–8 runtime profile and map retained `cascade3` ids from
   the first direct fixture. They are renamed to bounded `cascade` identities;
   the fixture case id and evidence ref remain cascade-3 because they describe
   the observed sample.
4. The final-output architecture assertion still expected a validator that
   received output only. It now locks the immutable bound-input snapshot
   required by the inactive-candidate mutation audit.
5. The root FWConfig paragraph placed marker-count wording after the new
   `Chip_Num` policy, producing an ambiguous sentence. The marker invariant and
   zero-count policy are now separate statements.

No confirmed #219 contradiction remains at candidate freeze. The following are
real but separately allocated target-state gaps and must not be hidden or
pulled into this R3 diff:

- #188 owns NT51950/NT51951 fixed-layout DiffDLM masking and deletion of their
  interim DiffNFMerge selector warning path.
- #239 owns NT51928 `LDC` terminology, dual-capacity Standard Merge, and grouped
  DP Replace selection.
- #194 owns remaining headless-route convergence; #182 owns the later shared
  slot/readiness presentation; #196 owns final legacy runtime deletion.
