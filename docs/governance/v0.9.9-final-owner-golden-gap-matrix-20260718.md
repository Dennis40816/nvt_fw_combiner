# v0.9.9 最終 Owner Golden 缺口矩陣 — 2026-07-18

## 範圍與結論

這是 stable v0.9.9 最後一次 owner-supply 盤點。它只區分現有 evidence、
可核准的 fact-scoped alias、資料矛盾與真正缺件；不移動 payload、不改
manifest/test path、不建立 runtime alias，也不變更任何 workflow support。

所有 committed golden 的實體重組延後到內部 milestone `0.9.9.5`。該名稱目前
只是規劃標籤，不是四段式 stable SemVer tag。未來 canonical layout 為：

```text
testdata/golden/canonical/
  <IC>/
    <workflow>/
      <variant-or-version>/
        <topology>/
          <case-id>/
            inputs/
            expected/
            provenance/
```

相同 bytes 只保留一份。其他 IC/case 必須透過 manifest 中具體、可審查的
fact scope 指到它；禁止靠目錄 sibling lookup、檔名猜測或複製 payload 表示 alias。
失敗或不一致樣本只能放 `diagnostics/`，不能冒充 `expected/` golden。

## 判讀狀態

- **Git direct**：payload、size、SHA-256 與 provenance 都在 Git，可由測試直接讀取。
- **Approved alias**：owner 已核准限定事實的共用；不需要重複提供 BIN。
- **Record only**：文件有 hash/分析，但 Git 沒有 payload；未來 canonical test 無法讀取。
- **Inconsistent**：已提供資料彼此不屬於同一次正式 run，或實際 target bytes 不符；
  為避免混用，必須重交該 case 的完整同批資料。
- **Decision only**：不是 BIN 缺口，只缺 owner 對版本、topology 或 safety scope 的決定。

4. **DiffNFMerge.exe**：repository 已有 hash-pinned package；不要重傳。
