# v0.9.7 UI Token and Code-Size Inventory

Status: Candidate evidence. This inventory is not a `v0.9.7` release claim.

## Measurement method

The counts below include nonblank `.cs` and `.axaml` lines only. They exclude
`bin/` and `obj/` recursively, so generated files cannot distort a source-size
decision. Test scope is `.cs` and `.py` under `tests/`, with the same exclusion.

The baseline is commit `8f40547d` before the pill-radius token slice. The
current candidate snapshot is commit `f9e506f6`; this inventory-only update
does not change the measured source. Both measurements use the identical file
filter. The former intermediate snapshot `025c6005` was remeasured from its
Git tree to keep the comparison independent of local generated files.

| Scope | Baseline | Result | Delta |
| --- | ---: | ---: | ---: |
| Production source (`src/`) | 59,551 | 59,906 | +355 |
| Presentation subset (`src/NvtFwCombiner.Presentation.Avalonia/`) | 16,898 | 16,908 | +10 |
| Tests (`tests/`) | 41,974 | 43,395 | +1,421 |

The current production source remains below the 60K review threshold in the
Legacy Retirement Matrix. The source and test delta reflects V2 candidate
compilation, AB Combiner staging, and the corresponding regression coverage
added after the initial token slices. Relative to the `025c6005` intermediate
snapshot, production is `+12`, Presentation is `+12`, and tests are `+311`;
those changes are the spacing/typography token declarations and their direct
contracts plus the Python/Combiner AB parity coverage. This inventory is
recorded for review only: it does not authorize removal of profile, firmware,
test, or evidence code merely to restore an earlier line count.

## Retired Duplication

`NfcPillCornerRadius`, `NfcSurfaceCornerRadius`, and
`NfcCompactCornerRadius` are the sole owners of the shared pill, surface, and
compact geometry values. The two token slices replace 40 exact
`CornerRadius="999"` literals plus 27 exact `6`/`8` surface and compact
literals across the shared style library and views. They do not merge semantic
surface, badge, control, accessibility, localization, or workflow roles.

`TextBlock.compactStrongText` was an exact duplicate of
`TextBlock.compactTitle`. Its two report-template callers now use the retained
role, removing one five-line style definition without changing typography or
report content.

`NfcSpace2`, `NfcSpace4`, `NfcSpace8`, `NfcSpace12`, and `NfcSpace16` now own
the repeated layout scale. `NfcFontSize10` through `NfcFontSize14` own the
repeated compact typography scale. The UI smoke contract rejects those raw
spacing and font-size literals outside `ThemeTokens.axaml`, while retaining
one-off geometry and semantically distinct text roles.

The UI smoke contract verifies that every shared color, shadow, and corner
radius token has a unique key, resolves from the application resource tree,
and that no Presentation XAML reintroduces the retired shared-radius literals.
The shell architecture test keeps the button style bound to the shared pill
token.

Presentation C# color literals fall from 68 to 23. The shared theme grows
from 54 to 67 `SolidColorBrush` definitions because 13 previously C#-owned
colors now have one XAML token owner. The remaining 23 Presentation C# color
literals belong to the Hex Editor immediate renderer exception recorded below.

Four old-branch slices had exact retained behavior and direct regression
coverage:

- firmware fact badges retain `Label`, `Value`, and `IsWarning`, while the
  shared styles own normal and warning colors;
- slot completion retains `HasFile`, `IsOptional`, and the localized
  requirement label, while ordered selectors preserve missing, selected, and
  optional states;
- slot icons retain enum kind, vector geometry, and accessible tooltip text,
  while Avalonia's built-in equality converter maps the five icon classes to
  shared palette styles; and
- Replace coverage retains data-bound fill, `IsChanged`, and `ChangeLabel`,
  while shared styles own changed/kept badge and outline chrome. Plain Merge
  bar and list templates remain unstyled by the Replace marker selectors.

The old branch's broad palette/template migration was not retained. The
current base already owns those exact colors, typography, spacing, radii,
shadows, and modal scrims in `ThemeTokens.axaml`; importing the old `UiBrush.*`
hierarchy would create a second token owner. Report outcome, navigation,
danger-button, row-divider, and broad template replacements were likewise
already represented by current shared tokens or semantic styles.

The `-29` production result is a consequence of deleting exact ViewModel
presentation projections, not a line-count target. The `+202` test result is
the direct visual-state, accessibility-preservation, token-ownership, and
architecture coverage required for those deletions.

## Audited Retentions

The exact-setter scan found two deliberately retained groups:

- `Border.surface`, `Border.modalSurface`, and `Border.fileDropZone` share
  their current visual setters but represent stable page, modal, and drag-drop
  roles. Collapsing them would remove the role boundary needed for future
  accessibility or interaction-specific changes.
- `TextBlock.pageSubtitle` and `TextBlock.supportingText` share typography but
  distinguish a page header from in-flow explanatory text. They remain
  separate localization and layout roles.

The remaining direct corner radii are one-off geometry: `0` for a separator
row, `2` for coverage-segment bars, `3` for the Hex editor cell, and `10` for
the workflow card. They are not shared design tokens.

## Decision Rule

Line count is an observation, not a deletion target. A later candidate may
retire a UI or compatibility definition only when all of the following hold:

1. one retained owner has identical behavior and semantic scope;
2. direct UI smoke, accessibility, and architecture coverage remains; and
3. no firmware fact, profile decision, processor rule, or localized meaning
   moves into Presentation code.

Tests, manifests, goldens, owner evidence, and required compatibility paths
are never deletion candidates merely to reduce this inventory.
