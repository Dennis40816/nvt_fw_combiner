## Lifecycle grammar ratchet

The implementation must preserve all of these closed rules:

1. Presentation owns exactly one shell preload lifecycle. Feature data and
   semantic publication stay in the existing typed catalog, report/history,
   diagnostics, inspection, filesystem, and external-environment owners.
2. Every queued progress, terminal, dispatcher, and accessibility callback for
   an allocated attempt carries `(shell session generation, stable stage id,
   monotonically increasing attempt number)`. Pending or dependency-blocked
   stage-state updates still carry the shell-session generation and stable
   stage id, but expose no current attempt identity until work is admitted.
   Selection inspection and external requests keep their separate never-reused
   request generations.
3. Every allocated attempt has exactly one terminal outcome. Per stage,
   Presentation retains at most the current attempt plus the immediately prior
   terminal summary; a third attempt deterministically evicts the older summary.
   Summaries contain lifecycle identity/state/diagnostic only, never copied
   feature data.
4. Catalog is the sole required startup stage and runs alone. After its typed
   publication is applied, optional non-UI work uses at most **two workers**;
   UI materialization stays serial on the background dispatcher.
5. Percentage is monotonic and local to one named stage's truthful work units.
   The UI may show `stage index / admitted stage count`, but heterogeneous
   route, byte, manifest, inspection, and view units are never summed into a
   fake aggregate percentage. Unknown totals remain indeterminate; timers and
   duration estimates do not invent progress.
6. Required failure offers Retry and Cancel startup/exit. Optional failure is
   isolated and offers Retry, Skip, or Continue; cancelling remaining optional
   preload cannot cancel an active Preview or Build.
7. Shell preferences remain a bounded pre-window prerequisite and contribute
   trace evidence only. Selection-triggered inspection uses a separate workflow
   lifecycle. Application-owned Preview/Build progress remains excluded from
   the shell lifecycle.
8. Closing cancels the active shell session and waits at most five seconds for
   drain. Stale, decreasing, non-finite, duplicate-terminal, and post-terminal
   updates cannot mutate observable state or publish a feature result.

These rules are architecture constraints, not a demand for one untyped result
envelope, service locator, plugin registry, ambient progress slot, or second
verifier.
