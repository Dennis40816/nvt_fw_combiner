## VM-01 — version catalog, snapshots, and Application policy

- Outcome: one typed Application owner for catalog/inventory/discovery/install,
  activation, retention-review, and delete decisions.
- Acceptance: strict v1 catalog DTO/schema and bounds; immutable version/status
  snapshots; stable issues; newer-version selection; generation supersession;
  explicit consent; active/delete/LKG-warning policy; no firmware dependency.
- Non-goals: filesystem, ZIP, process, UI, packaging.
- Mutable surfaces: Contracts schemas/DTOs; Application version-management
  namespace; focused Contract/Application tests; architecture guards.
- Blockers: none.
- Risk/evidence: R2 public internal contract; red/green narrow Contract and
  Application tests plus architecture dependency checks.
- Deletion criterion: no compatibility path; only the new typed owner exists.

## VM-02 — content verification, staging, inventory, and guarded deletion

- Outcome: Infrastructure implements stable source/catalog/package reads,
  safe extraction, inner-manifest verification, atomic version promotion,
  installed integrity inventory, state persistence, and exact guarded delete.
- Acceptance: every catalog/archive/path/size/hash/reparse/failure bound in the
  spec; location-independent identity; no partial install; typed diagnostics;
  deterministic cancellation and idempotence.
- Non-goals: process activation, firmware execution, UI.
- Mutable surfaces: Application ports; Infrastructure version-management
  adapters; focused Infrastructure tests with temp directories/archives.
- Blockers: VM-01.
- Parallel: independent adapter seams may be implemented in one ticket but one
  writer preserves shared state/path ownership.
- Risk/evidence: R2 filesystem/destructive boundary; exact target-root tests,
  path escape/reparse tests, failure injection, scoped Polytail.

## VM-03 — stable launcher, activation readiness, and rollback

- Outcome: a minimal stable launcher selects verified side-by-side payloads,
  supervises the one-use ready channel, commits health, and rolls back once.
- Acceptance: pending journal, process start/exit/timeout/ready, active and LKG
  state transitions, fallback guard, no oscillation, no command-line secret,
  deterministic fake and real helper-process tests.
- Non-goals: catalog UI, self-updating the launcher, firmware logic.
- Mutable surfaces: launcher project/entry point; Application activation port;
  Infrastructure process/ready adapter; launcher integration tests; solution.
- Blockers: VM-01; consumes VM-02 installed verification before completion.
- Risk/evidence: R2 process and recovery boundary; architecture review and
  Windows process evidence.
