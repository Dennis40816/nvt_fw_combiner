## VM-01 — version catalog, snapshots, and Application policy

- Outcome: one typed Application owner for catalog/inventory/discovery/install,
  activation, retention-review, and delete decisions.
- Acceptance: strict v1 catalog DTO/schema and bounds; immutable version/status
  snapshots; stable issues; newer-version selection; generation supersession;
  explicit consent; active/delete/LKG-warning policy; no firmware dependency.
- Non-goals: filesystem, ZIP, process, UI, packaging.
- Mutable surfaces: Contracts schemas/DTOs; Application version-management
  namespace; focused Contract/Application tests; architecture guards.
- Blockers: none.
- Risk/evidence: R2 public internal contract; red/green narrow Contract and
  Application tests plus architecture dependency checks.
- Deletion criterion: no compatibility path; only the new typed owner exists.

## VM-02 — content verification, staging, inventory, and guarded deletion

- Acceptance: every catalog/archive/path/size/hash/reparse/failure bound in the
  spec; location-independent identity; no partial install; typed diagnostics;
