# v1.0.0 code-size and single-owner review

Status: final-candidate implementation baseline; no allowance for later growth.

## Fixed implementation object

The exact production object is bound by the final
`RELEASE-100-FINAL-01` capability record and its immutable reviewed-head path
digest. The record may be finalized only after the complete candidate is
committed and independently reviewed. Later commits must not silently replace
the firmware executor used by the v0.9.16 parity contract.

The measurement is reproducible with `measure_code_size(Path('.'))` from
`scripts/code_size_policy.py`. It counts nonblank physical source lines and
excludes generated `bin`, `obj`, release, artifact, and cache directories.

| Governed measure | Files | Nonblank lines |
| --- | ---: | ---: |
| Full C# and AXAML production tree | 829 | 120,996 |
| Non-UI/runtime production | 569 | 83,414 |
| Domain + Profiles | 157 | 20,632 |
| Application | 234 | 38,182 |
| Bootstrap + CLI + Desktop + Launcher | 38 | 4,058 |
| Infrastructure + Contracts + CRC worker | 140 | 20,542 |

The four runtime slices sum exactly to 83,414. The duplicate profile/contract
JSON measure is zero groups, zero copies, and zero duplicated nonblank lines.
The policy preserves the frozen pre-v0.10.5 base ratchets and records only the
exact difference to each measured value as a named, non-transferable v1.0.0
allowance. The effective ceilings are therefore exactly the values above. A
later increase fails repository validation; a decrease requires lowering the
corresponding allowance.

The separate broad repository inventory is descriptive and is reported in the
release handoff after the final evidence record is complete; it is not a
substitute for the executable slice ratchets above.

## Minimality and ownership findings

The v1.0.0 surface is large, but the reviewed convergence does not add a second
firmware planner, executor, profile authority, Registry admission or replica
selection owner, Registry publisher, update catalog owner, parity comparator,
or support classifier.
The relevant ownership remains:

- profiles and the shared compiler own ranges, mappings, validations, output
  naming, and support facts;
- the shared Application run services own typed fixed-workflow execution;
- the canonical Infrastructure route inventory projects each General Replace
  topology/input-mode declaration into one typed IC-number choice; Application
  transports and validates that choice without parsing route identity strings;
- Infrastructure implements file, Registry, package, and platform adapters;
- `ManagedPathSafety` is the sole Version Infrastructure owner for exact
  absolute-path normalization, device/alternate-stream rejection,
  platform-path comparison, and reparse-chain admission; Registry and Catalog
  adapters consume it rather than reimplementing those rules;
- filesystem and HTTP Registry adapters acquire bounded bytes; the shared
  strict document parser owns wire admission, while `ReplicatedUpdateSourceRegistry`
  is the sole Application replica-selection owner;
- `scripts/edit_update_source_registry.py` is the sole cooperating live
  Registry publisher and never enters package identity or checksums;
- `scripts/v0916_parity_certification.py` compares independently built frozen
  executors and cannot promote missing or mismatched evidence;
- Presentation projects typed state and does not re-infer firmware semantics.

The increase since the historical 45,214-line runtime baseline is attributable
to already approved Version/Launcher/Registry management, complete fixed
Standard/AB/CtrlRAM authoring, memory-layout/report evidence, bounded selected
file inspection, and the shared desktop experience. Removing any of those
owners now would remove required v1.0.0 behavior rather than consolidate a
duplicate implementation.

The final minimality review found no duplicate runtime owner after the
path-safety consolidation. Small same-owner control-flow cleanup remains in
the Registry publication scripts, but changing its lock, rollback, or operator
ordering immediately before release would add risk without removing an
authority. Thin tested publisher seams likewise remain within their existing
owner. The Self-test scheduler hop is intentionally retained: an executable UI
regression proves that a synchronously slow source inspection must run outside
the UI context. A redundant package-equivalence loop was removed after the
exact changed-path set equality made it unreachable.

The largest retained presentation aggregate is
`WorkflowSessionPresentationViewModel` at 2,578 lines across 11 partial files.
This aggregate owns one typed workflow-session presentation boundary; the
release review found no second firmware or workflow execution owner inside it.
Its exact 2,578-line named ceiling records the current release object and
prevents further growth. `ShellTextResources` remains at 2,501 lines across 13
localized partial files under its exact named ceiling. Both are organization
and analyzer-debt candidates for v1.1.0, not safe release-eve deletions.
`V2CompositionPlanCompiler` remains below its existing 2,798-line ceiling, and
`MainWindowViewModel` remains below 985 lines.

## Decision

The implementation is acceptable as the minimum complete v1.0.0 feature set.
This is a one-time exact rebaseline authorized by the owner, not a waiver for
future size. No unexplained duplicate semantic owner or unused runtime module
was found in the fixed-object architecture and Polytail reviews. Further
structural reduction belongs to v1.1.0 and must preserve Golden bytes, typed
contracts, single ownership, and all release evidence.

Required verification before release remains:

- exact code-size policy and structure verification;
- Release build with zero warnings and errors;
- Registry, Version, architecture, parity-contract, Golden, and release-policy
  suites;
- independent fixed-head technical reviews; and
- the external firmware-owner, release-owner, clean-machine/network,
  accessibility, and visual human gates declared by the release records.
