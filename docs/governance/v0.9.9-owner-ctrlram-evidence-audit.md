## Expected-only evidence method

The official owner system supplies the final expected firmware and the physical
CtrlRAM inputs, but cannot export a separate pre-replacement `base.bin`. The
following expected-derived method was therefore used for evidence intake:

1. Copy the official final expected firmware to a temporary work image.
2. Replace only the effective bytes written from each supplied physical
   CtrlRAM input with deterministic sentinel bytes. For a zero-offset short
   source, effective length is `min(source length, declared maximum)`; the
   untouched tail is not overwritten.
3. Run the normal Workbench CtrlRAM Replace path and the manifest-pinned Legacy
   Combiner 1.13.0 (`sha256`
   `ed6b58289cc780f73d36b831f5424cef44ad93187ba7518d36df6a77ad0c76bf`)
   with the cataloged command order, staging bindings, and write authority.
4. Compare every output byte with the official expected firmware and classify
   every difference by its declared half-open range.

This method can prove the selected input bytes, offsets, effective lengths,
short-source tail preservation, physical-file reuse, command execution, and
declared processor writes. It cannot independently prove the historical
pre-replacement base, base-selection compatibility, or unchanged bytes copied
directly from the expected output. The result must therefore be named
`owner-expected-output + expected-derived-sentinel range parity`, not a direct
base-backed product golden or independent full-byte parity. It cannot promote
runtime support without the firmware-owner decisions below.

The NT51927 2-chip and 3-chip physical copy blocks all match their respective
expected outputs. Reconstructing the Standard Merge DP/TP ownership also
matches those outputs. Their decoded Common FW versions are `1.3.2` and
`1.4.0`, respectively; using the cataloged `PostbuildSetup_51927_1.4.1` for
those versions still requires an explicit firmware-owner fact decision.

The NT51950 single case directly exercises two size-policy boundaries:

- `NF_Ctrlram.bin` is 2,816 bytes while the command declares a maximum of
  `0x2A10` (10,768) bytes. The compatible behavior copies 2,816 bytes and
  preserves the remaining 7,952 target bytes.
- `Normal_Ctrlram.bin` is 655,360 bytes while the declared section consumes
  only 23,552 bytes. The explicit CtrlRAM truncation policy consumes the
  declared prefix and reports a warning.

The NT51951 single case fails before any allowed-difference decision. It has
3,773 payload differences: two bytes at `[0x25620, 0x25621)` and
`[0x25623, 0x25624)`, plus 3,771 bytes across the Normal payload span
`[0x2857C, 0x294F8)`. The other 16 differences are the expected Header
CRC/Header Copy CRC fields. The supplied final name identifies a different
firmware revision from the supplied Initial/TP files, and the decoded project
identifier also conflicts with the accompanying project marker. This case
needs a matching same-run Normal/Initial/TP/final set; it cannot use the
NT51950 alias statement to hide the mismatch.

The NT51926 Common FW 1.4.1 cascade package remains a self-replacement control.
Its FlashCode equals the already recorded base, its TP firmware is an exact
prefix, and its physical inputs already match the target bytes. It does not
provide an independent final expected output for retirement or promotion.

## Firmware-owner decisions still required

The following decisions are explicit R3 gates. None is inferred from matching
bytes:

1. Confirm each named final firmware is the official postbuild output and
   confirm the same-run provenance of its physical CtrlRAM inputs.
2. Accept or reject the expected-derived-sentinel method for static
   declaration/V2 migration evidence, with no runtime-support promotion.
3. Confirm the exact Legacy Combiner 1.13.0 command order, staging/read/write
   authority, and that the only allowed residual classes are Header CRC and
   Header Copy CRC.
4. For NT51927 2-chip and 3-chip, approve the decoded Common FW versions against
   the selected postbuild category, chip-count mapping, shared VN mapping,
   composite NF ordering, and left/right Normal/MP physical-file mapping.
5. For NT51950 single, approve 2,816-byte NF as an official short source,
   `0x2A10` as a maximum rather than an exact length, preserved tail behavior,
   and prefix-only consumption of the oversized Normal input.
6. Reject the current NT51951 single package or supply the matching
   Normal/Initial/TP/final set. No parity or alias approval is valid while the
   3,773 payload-byte mismatch remains unexplained.

Until these decisions are recorded, the evidence may improve diagnostics and
the owner handoff, but it cannot retire a production authority, change a
profile/range, or satisfy the stable release R3 gate.
