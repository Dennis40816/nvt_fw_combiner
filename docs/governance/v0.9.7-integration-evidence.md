# v0.9.7 Integration Evidence

Status: release-candidate integration record; not a firmware-support promotion.

## Baseline and retained history

The `0.9.7` integration branch fast-forwards the existing local milestone branch
to `origin/0.9.6` at `6213e434`, then retains only these independently reviewed
forward-port phases:

- AB evidence applicability and runtime-admission guards from
  `feature/0.9.3/ab-evidence-forward-port`;
- compiled final-output validation and the non-routed NT51926 CtrlRAM candidate
  from `feature/0.9.5/ctrlram-v2-convergence`; and
- the four audited semantic-state token slices from
  `feature/0.9.7/ui-token-consolidation-audit`.

The stale `feature/0.9.3/ab-combiner` history is excluded because it mixes
private and out-of-scope changes. The older full UI-token branch is excluded
because its broad palette hierarchy would duplicate tokens already owned by
the current base. Candidate-intake and DP-retirement feature histories are not
replayed because their retained outcomes already exist on the `0.9.6` lineage.

## Commit-log quality gate

Every commit after annotated tag `v0.9.2` must have one reviewable phase and a
Conventional Commit subject using an explicit type and, where useful, a narrow
scope. The final integration audit rejects subjects longer than 72 characters,
leading or trailing whitespace, `WIP`, `TODO`, temporary/checkpoint wording,
and `fixup!` or `squash!` commits. Published feature history is not force
rewritten; duplicate or obsolete branches are excluded at integration instead.

The audit is performed over `v0.9.2..HEAD` immediately before the PR handoff,
and its count/result is recorded in the PR evidence.
