## Pre-1.0 owner override

On 2026-07-21 the owner raised the aggregate production C#/XAML ceiling to
75,000 nonblank lines for the remaining pre-1.0 releases. This supersedes the
earlier 60,000-line aggregate ceiling and the v0.9.9 exit target. The value is
development headroom, not a growth target: it prevents useful layout,
instrumentation, and regression coverage from being compressed merely to stay
within a nearly exhausted aggregate budget.

The predecessor measured 59,999 lines before the owner-requested report-padding
and Build-placement correction; that correction measured 60,014 lines before
this override. The ceiling change therefore records an explicit product-owner
decision instead of disguising an unexplained implementation increase.

The override does not relax the exact duplicate-JSON ratchet, the default
partial-type limit, Polytail oversized-file review, firmware safety checks,
test/golden evidence, or package-size gates. On the owner's later v0.9.12
clarification, the two historically named partial aggregates changed from
exact-equality ratchets to 4,500-line ceilings for the remaining pre-1.0 work.
This permits reviewed UI and orchestration additions without making harmless
line reductions fail verification. The aggregate and named ceilings must be
rebaselined at 1.0.0 from the reviewed architecture and shipped feature set;
they must not be raised automatically to match whatever the tree contains.

The pre-1.0 named ceilings are 4,500 lines for both
`WorkbenchCompositionService` and `MainWindowViewModel`. Hash-pinned bundle
loading and built-in V2 registration ownership live in focused Bootstrap
collaborators; the Workbench partials retain routing and orchestration. The
ceiling remains an architecture alarm, not permission to add firmware semantics
to Presentation or to grow either aggregate without review.

## v0.9.8 reduction order

1. Remove checked-in schema copies whose bytes already have one canonical
   contract owner; package or generate them from that owner without adding a
   second compiler.
2. Replace repeated built-in bundle/profile registration tables with one
   manifest-pinned registry consumed by Bootstrap and packaging.
3. Move test-only synthetic profile helpers out of production assemblies.
4. Delete compatibility projections only after every production consumer has
   direct V2 parity and the Legacy Retirement Matrix is updated.

On 2026-07-16 the owner accepted the exact 56,742-line ratchet as the final
`v0.9.8` source-size result and ended further 0.9.8 compression; this supersedes
the earlier 56,000-line stretch gate. The convergence targets still include at
most 2,000 redundant exact JSON lines and 4,500 lines in
`WorkbenchCompositionService`. The `v0.9.9` production exit gate remains at
most 54,000 lines. These targets must not be met by deleting evidence or
weakening a firmware safety check.

## Release-package budget

The `v0.9.7` CI package baseline is 57,501,699 compressed bytes for the inner
Windows ZIP. The application executable contributes 46,858,101 compressed
bytes and 107,884,957 uncompressed bytes; the required self-contained runtime
dominates both figures. Source-size reduction is therefore not represented as
an equivalent package reduction.

The owner-approved maximum is 1% growth over that baseline: 58,076,715 bytes.
The package ratchet belongs in the release smoke path and must use a clean,
reproducible artifact. Trimming, single-file publishing, dependency changes,
and removal of self-contained runtime files require separate release review
and clean-machine evidence.

## Forbidden shortcuts

- deleting tests, golden fixtures, evidence manifests, or owner-review gates;
- removing useful comments, expanding one-line formatting, or generated-source
  tricks to manipulate the nonblank-line count;
- replacing typed validation with unchecked JSON or UI-only restrictions; or
- removing or bypassing the approved Legacy Combiner runner.
