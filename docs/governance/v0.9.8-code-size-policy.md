# v0.9.8 Code-Size Policy

## Baseline

The baseline is the `v0.9.7` merge commit
`b1616e5b5c7275548f75a2fa17ad16ec94e35c68`.

| Metric | Files/groups | Exact ratchet |
| --- | ---: | ---: |
| Production C# and XAML under `src/` | 559 files | 60,237 nonblank lines |
| Byte-identical JSON duplication across `profiles/` and `docs/contracts/` | 16 groups / 16 redundant copies | 10,781 nonblank lines |
| `WorkbenchCompositionService` partial aggregate | 43 files | 6,033 nonblank lines |
| `MainWindowViewModel` partial aggregate | 22 files | 3,035 nonblank lines |

All measurements exclude generated and cache directories. Exact JSON
duplication counts only the redundant copies, not the retained canonical copy.

The current production ratchet is 56,730 lines. Verified convergence has moved
test-only fixtures out of production, removed exact duplicate ownership, and
shared equivalent report, Bootstrap, tool-resolution, byte-range, and immutable
snapshot mechanics without changing firmware behavior or support claims. The
Hex Editor context menu now binds directly to the existing ViewModel commands
instead of maintaining duplicate forwarding handlers; no generated-source
transfer or feature removal is counted as convergence. Standard Merge, General
Merge, and Replace now share one UI-owned run lifecycle while preserving their
existing service calls, cancellation policy, error reports, and cleanup order;
the `MainWindowViewModel` aggregate is ratcheted at 2,847 lines. DP, CtrlRAM,
and General Replace CLI commands also share one fail-closed output and report
lifecycle while retaining workflow-specific input construction and service calls.
Canonical NT-prefixed IC identifier normalization now has one Profiles owner;
numeric-only IC extraction remains separate because its output contract differs.
The Debug-only repository-fixture autoload was retired so Debug and Release
startup both require explicit launch options; distributed behavior is unchanged.
Equivalent badge and centered technical-input geometry now use shared Avalonia
style roles while preserving each control's semantic class and state overrides.
Unbound Merge/Replace inspector text projections and test-only shell commands
are retired; the real Home workflow command path now owns their remaining test.
Unbound report-view flags, labels, and constructor arguments are also retired;
the report schema, parsed collections, and displayed evidence remain unchanged.
Tests-only report summary, triage, and evidence-row projections are retired in
favor of the Outcome, Next Step, and evidence collections the UI actually binds.
Unbound footer, disabled-segment, success-surface, technical-header, and Hex
Editor mode-selection roles are also retired; the visible fill-mode toggle and
range-edit behavior remain unchanged.
Test-only readiness aliases, settings preference summary rows, footer state, and
unbound bilingual labels are retired; preview command readiness, build readiness,
visible preference status, and language switching remain covered directly.
The footer retirement also removed its stale XML summary while General Replace
continues to assert build readiness after preview.
Report-history and preference persistence now share one best-effort JSON,
default-path, and atomic-promotion mechanism while retaining their distinct
schemas, fallback values, and round-trip behavior.
Immutable report rows and groups now initialize directly from their constructor
inputs, while counts and visibility flags derive from the retained evidence
collections instead of duplicating mutable presentation state.

The current `WorkbenchCompositionService` aggregate is 4,482 lines, below its
4,500-line convergence target. Hash-pinned bundle loading and built-in V2
registration ownership now live in focused Bootstrap collaborators; the
Workbench partials retain routing and orchestration.

## v0.9.8 reduction order

1. Remove checked-in schema copies whose bytes already have one canonical
   contract owner; package or generate them from that owner without adding a
   second compiler.
2. Replace repeated built-in bundle/profile registration tables with one
   manifest-pinned registry consumed by Bootstrap and packaging.
3. Move test-only synthetic profile helpers out of production assemblies.
4. Delete compatibility projections only after every production consumer has
   direct V2 parity and the Legacy Retirement Matrix is updated.

On 2026-07-16 the owner accepted the exact 56,742-line ratchet as the final
`v0.9.8` source-size result and ended further 0.9.8 compression; this supersedes
the earlier 56,000-line stretch gate. The convergence targets still include at
most 2,000 redundant exact JSON lines and 4,500 lines in
`WorkbenchCompositionService`. The `v0.9.9` production exit gate remains at
most 54,000 lines. These targets must not be met by deleting evidence or
weakening a firmware safety check.

## Release-package budget

The `v0.9.7` CI package baseline is 57,501,699 compressed bytes for the inner
Windows ZIP. The application executable contributes 46,858,101 compressed
bytes and 107,884,957 uncompressed bytes; the required self-contained runtime
dominates both figures. Source-size reduction is therefore not represented as
an equivalent package reduction.

The owner-approved maximum is 1% growth over that baseline: 58,076,715 bytes.
The package ratchet belongs in the release smoke path and must use a clean,
reproducible artifact. Trimming, single-file publishing, dependency changes,
and removal of self-contained runtime files require separate release review
and clean-machine evidence.

## Forbidden shortcuts

- deleting tests, golden fixtures, evidence manifests, or owner-review gates;
- removing useful comments, expanding one-line formatting, or generated-source
  tricks to manipulate the nonblank-line count;
- replacing typed validation with unchecked JSON or UI-only restrictions; or
- removing or bypassing the approved Legacy Combiner runner.
