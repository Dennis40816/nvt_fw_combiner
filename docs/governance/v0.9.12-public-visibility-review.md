# v0.9.12 Public Visibility Review

- Decision date: 2026-07-22
- Owner decision: remain Public through stable `v1.0.0`; become Private afterward
- Applies to: repository, pull requests, source archives, and stable release metadata

## Decision

The earlier plan to make the repository Private after `v0.9.11` is superseded.
The repository remains Public while `v0.9.12`, `v0.9.13`, and the stable
`v1.0.0` release are developed and published. After stable `v1.0.0` completes,
the repository becomes Private before post-`v1.0.0` development unless the
owner records a newer explicit decision.

Changing visibility later cannot retract commit history, source archives,
caches, clones, or forks that were already public. Public-release review must
therefore continue to treat every committed object and release asset as
permanently disclosed.

## Existing public inventory and v0.9.12 delta

The repository already tracks owner-approved canonical golden BIN payloads,
including AB cases whose provenance records classify them as private-owner-
approved golden evidence, plus the manifest-pinned Legacy Combiner boundary.
Those objects and their earlier history are already public. The owner accepts
that existing exposure while keeping the repository Public through `v1.0.0`.

The `v0.9.12` visibility/AB-planning closure commit adds no new BIN, archive,
credential, signing key, token, or private payload. This is a delta statement,
not a claim that the repository or source release contains no firmware bytes.

The ignored owner-handoff `.7z` remains outside Git, the pull request, and the
release package. It is not accepted evidence and must not be staged, copied to
an artifact, or represented as passing repository inventory.

GitHub-generated source `.zip` and `.tar.gz` archives contain the exact tagged
Git tree, including already tracked owner-approved golden payloads. The Windows
portable ZIP contains only the allowlisted runtime/profile/tool and selected
fixture boundary enforced by packaging tests; it never sweeps owner-handoff
working directories. Release notes and hashes identify the exact tag.

## v1.0.0 closure gate

Stable `v1.0.0` release closure must record one of these outcomes:

1. repository visibility changed to Private after the stable release; or
2. a newer dated owner decision explicitly replaces this schedule.

Neither outcome changes firmware support status, signing authority, branch
protection, profile admission, or release-asset approval. Those retain their
own review and human gates.
