# v0.9.9 Legacy Retirement Evidence

## Decision

At baseline `c3b77363`, no remaining legacy authority can be deleted safely as
a whole. The remaining duplication is architectural rather than byte-identical:
trusted V2 profiles own the migrated Standard Merge and DP Replace paths, while
CtrlRAM and General Replace still depend on Workbench-built profiles and flash-map
projections. The forwarding metadata facade and the static Combiner Postbuild command
and TP flash-map fact declarations have now been retired into hash-pinned
repository data catalogs.

The original inventory was R0. ADR 0024's TP/full-Flash convergence is R3
because it adds a schema/compiler processor-prefix contract and a second exact
map capacity. It does not change a command, write authority, runtime route, or
support claim.

## Measured retirement surface

The accepted `v0.9.8` production ratchet is 56,742 nonblank C#/AXAML lines.
The v0.9.9 TP semantic/Workbench/UI convergence, bilingual-resource
consolidation, drop-zone convergence, CLI report-writer convergence, and
firmware-region ordering convergence, config-authority, and dormant V1 compiler
retirement phases previously lowered the interim ratchet to 55,031 lines.
After the later support/UI phases and this facade retirement, the current
working branch measures 55,366 production lines, a 4,609-line Workbench
aggregate, a 2,731-line MainWindowViewModel aggregate, and 1,055 exact-duplicate
JSON lines. These are measurements, not accepted higher ratchets. The phases
retire only unbound projections, wrappers, and duplicated
bilingual assignment and region-ordering structures plus the static Postbuild
command/range declarations. The latest phase also removes the raw IC-number
list projection and forwarding-only metadata/map overloads while retaining
grouped UI choices and branch-rule request validation; none of these phases
promote an IC/mode. The remaining gap to the owner-approved 54,000-line stable
gate is 1,366 lines. The retained CtrlRAM compatibility path additionally fails
closed unless exactly one processor stages source bytes into processor-owned
CtrlRAM ranges within declared postbuild write authority.
The pre-retirement compiler plus the config-backed map query adapter accounted
for 990 nonblank C# lines before caller cleanup:

| Authority | Files | Nonblank lines | External production caller files |
| --- | ---: | ---: | ---: |
| `CompositionProfileCompiler` | 8 | 699 | 2 |
| `BuiltInTpFlashMapCatalog` config loader/query | 3 | 291 | 8 |

The compiler callers have now migrated or fail closed and the compiler graph is
deleted; the config-backed map query remains because its display/planning
consumers are outside the frozen release scope. The `IcMetadataFacade` forwarding layer has been retired independently because
it owned no firmware fact or execution policy; projection parity remains locked
at `WorkbenchCompositionService`. Reaching the owner-approved `v0.9.9` ceiling
of 54,000 is closed by the evidence-backed compiler migration and deletion. It did not come from
deleting evidence or weakening validation. This is a measured boundary, not a
deletion claim or runtime-promotion approval.

The release-exposed V1 compiler route is retired, but a bounded Domain/Application
compatibility type surface remains: `CreateLegacy`,
`LegacyProfileCompilationAuthority`, and `LegacyRuntimeExecutable`. There is no
production creator or caller after this phase, and architecture tests keep that
creator count at zero; therefore no UI, CLI, or Workbench request can enter it.
The surface is retained only to avoid expanding the frozen v0.9.9 change into a
public Domain/Application contract break. It is not a fallback, support route, or
claim that V1 runtime types have been physically eliminated. A later contract
version may remove it only with its own architecture review and compatibility gate.

The Legacy Combiner 1.13.0 executable and constrained staged runner are not
retirement targets. The duplicated static declarations have moved to
`profiles/built-in/ctrlram-postbuild-v2/catalog.json` and `flash-map.json`; the loaders reject hash,
unknown-field, enum, range, duplicate-id, and reviewed argument-allowlist drift.
The runner remains the sole writer for approved Combiner-owned CRC/header changes.

## Existing V2 coverage

The built-in routed CtrlRAM Replace V2 profiles cover NT51926 Common FW 1.4.1
cascade and Common FW 2.0.0 single/cascade without a TP firmware-version edit.
They accept exactly `0x3C000` TP-work or `0x40000` full-Flash base forms and
selected physical Normal/DIFF/MP/VN/NF sources through the pinned Combiner
1.13 invocation profile. For full Flash, the shared engine stages only
`[0,0x3C000)` and preserves `[0x3C000,0x40000)` byte-for-byte.

The owner-authorized TP-base case now proves full-output V2-candidate parity
with its archived Legacy Combiner 1.13.0 output. The exact full-Flash owner
intake also proves V1/V2 byte parity and tail preservation, but remains an
expected-derived self-replacement without an independent pre-replacement base.
No support promotion is claimed.

The final 2026-07-18 NT51926 2.0.0 direct cases close exact single/cascade
engineering parity: Standard Merge decodes Common FW 2.0.0, PID `0x1309`, and
chip count 1 or 3 from FWConfig Backup; V1 and V2 output bytes and SHA-256 are
identical after one two-command processor session. Each output differs from the
owner expected by exactly 16 bytes at the two Header CRC/Header Copy CRC words
and their copied-header counterparts. CtrlRAM payload difference is zero,
inputs remain immutable, and the full-Flash tail is preserved. These facts
route only the exact profiles and do not promote support.

It remains `executable-candidate` and is routed through the shared UI/CLI
Workbench boundary for that exact slice. The scoped Legacy Combiner and route
parity blockers are closed. Its remaining blocker is firmware-owner review of
the exact command, prefix authority, and writes. The residual Workbench path
still:

- permits a non-empty subset of the mapped CtrlRAM regions;
- catalogs, routes, and plans all 13 IC rows and their single/cascade/numeric
  branches without making a support claim;
- selects versioned NT51926 and NT51930 postbuild categories from the base;
- exposes a Build-only TP firmware-version edit that remains R3-gated on its
  existing field/range, expected-output, and firmware-owner evidence;
- plans display, coverage, warnings, command evidence, reports, and naming; and
- admits General Replace mappings only through its current protected-range and
  postbuild selection policy.

The committed NT51926 and NT51927 self-replacement fixtures prove that the
Workbench route and staged tool can execute. For NT51926 Common FW 1.4.1
cascade, commit `67b8144b` routes the runtime profile, requires the TP-base
result to match the archived Legacy Combiner 1.13 full output, while the
pre-retirement control records independent full-Flash byte/tail parity. This
closes the
scoped route gate, not firmware-owner approval of exact write authority or the
remaining version/count/edit cases.

The same hash-pinned NT51926 family also includes the routed
`nt51926-general-replace-dp-single-candidate`. Its dedicated physical map
accepts only a `0x40000` full-Flash reference and authorizes only explicit
DP mappings within `[0x3E000,0x40000)`. It has no metadata, static operation,
validation, or processor authority. Direct regression uses the same immutable
base/source and requires the routed V2 output to match independently composed
expected bytes; CLI and UI tests lock the routed profile,
report, naming, and immutable base. Separate tests reject a `0x3C000` TP-only
base and TP/CtrlRAM targets. This is the first concrete General Replace runtime
migration slice, but it is limited to single-selector, full-Flash, file-backed
DP mappings. Patches/fills and every other IC/count/base/target fail closed.

## Retirement order

1. Keep the reviewed NT51926 1.4.1 cascade and 2.0.0 single/cascade routes
   pinned to ADR 0024, exact golden tests, and support-neutral profiles. Do not
   widen them while migrating the next exact case.
2. Migrate one directly evidenced IC/version/count family at a time. Static
   flash-map facts are already retired; replace their config query projections
   only after the resolved V2 map supplies every current consumer.
3. Route all CtrlRAM planning, display, coverage, metadata, Preview/Build, and
   report consumers through the reviewed V2 boundary. The forwarding
   `IcMetadataFacade` is already retired; retire `BuiltInTpFlashMapCatalog`
   only after no production consumer remains.
4. Keep General Replace limited to the exact NT51926 DP-only V2 route; protected
   TP/CtrlRAM targets, patches/fills, and all other shapes fail closed.
5. The static `LegacyCombinerPostbuildCatalog` and `CompositionProfileCompiler`
   are retired. Keep the hash-pinned postbuild data projection under parity tests.
   Remove the config-backed flash-map query adapter only when architecture tests prove it has no
   production consumers. Keep the Legacy Combiner executable, constrained
   runner, staging-copy isolation, host diff enforcement, and tool packaging.

## Protected invariants

- No range, command, processor write, alias, IC-count rule, or runtime support
  is inferred from this inventory.
- For zero-offset CtrlRAM sources, the declared section length is a consumption
  and write-authority upper bound: copy stops at source EOF and preserves the
  untouched base tail. A larger owner-supplied physical container is accepted
  only through the explicit CtrlRAM truncate-with-warning policy; only its
  leading declared span is staged, and trailing bytes never expand processor
  read/write authority. This owner-approved compatibility behavior is not
  whole-input exact-length authority.
- C# does not reimplement Combiner CRC/header algorithms. In particular, C#
  never writes the AB header CRC.
- NT51950/NT51951 AB use the full DP container as the base and do not require
  `map.txt`; Python parity is compared with the exact Legacy Combiner 1.13
  command.
- NT51919/NT51932 AB evidence applicability is closed by the explicitly
  approved NT51929 fact-scoped aliases; NT51950/NT51951 AB applicability is
  likewise closed by the approved workflow-logic alias. These decisions do not
  replace firmware-owner promotion review or the independent topology tests.
- Runtime/support promotion remains separate and requires owner review after
  byte evidence closes.
- The NT51926 CtrlRAM V2 candidate accepts only exact TP-work/full-Flash shapes.
  Scoped TP Legacy Combiner golden parity and full-Flash V1/V2 self-replacement
  parity are closed. Common FW 1.4.1 cascade without a version edit is routed;
  exact owner range review, other versions/counts/edits, and support promotion remain open.
- The NT51926 General Replace V2 candidate accepts only a full-Flash base and
  file-backed DP-only single-selector mappings. That exact slice is routed; it
  cannot be used to bypass TP/CtrlRAM Legacy Combiner postbuild, and patches,
  fills, other shapes, counts, and ICs retain their existing path.
