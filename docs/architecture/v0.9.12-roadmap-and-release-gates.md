# v0.9.12 Roadmap and Release Gates

Owner scope, 2026-07-21. This milestone removes golden-identity admission from
normal CtrlRAM production routing without weakening profile, map, processor,
range, immutable-input, or atomic-output authority. It also closes the
owner-reported interaction problems around silent no-output failures, selected
input state, Number/IC mismatch, unsafe page navigation, and the bottom-right
action rail. It makes no public support promotion.

## Runtime authority

1. Requested IC selects only its owner-declared family or fact-scoped alias.
   PID, filename, complete SHA-256, TP/Common FW display values, and fixture
   count never select family.
2. Common FW profiles cover half-open intervals beginning at `1.0.0`. NT51926
   uses `[1.0.0,2.0.0)` and `[2.0.0,infinity)`; a single-profile IC uses one
   `[1.0.0,infinity)` runtime profile even when the information field is missing.
3. Number selects a typed owner-provided plan: single, generic cascade, exact
   count, or one non-overlapping count range. NT51930 exposes single/`2–13`;
   NT51927 and NT51928 non-NB expose single/2/3.
4. FWConfig chip count is a post-selection cross-check. Contradiction with an
   exact plan requires an explicit confirmation or fails Build; it cannot
   silently reroute.
5. All 31 runtime interval/plan pairs across the 13 selectable ICs have trusted
   V2 routes. Runtime routes remain support-neutral until their per-plan direct
   output evidence and firmware-owner promotion gates close.

NT51928 non-NB has the same TP/CtrlRAM layout and postbuild plans as NT51927.
Its difference begins at DP/LDC address `0x40000`, so DP Replace separately
requires DP `[0x3C000,0x40000)` and LDC `[0x40000,0x62000)` while CtrlRAM
preserves `[0x34800,0x80000)`. NT51928 NB is not covered.

NT51950 and NT51951 have matching TP offsets, DiffDLM
`[0x33200,0x34600)`, and postbuild command contract for single/cascade.
Their image capacities remain `0x40000` and `0x80000`; LDC is packaged inside
the DP payload instead of exposed separately. AB remains a different workflow.

## Interaction acceptance

| Area | v0.9.12 acceptance |
| --- | --- |
| Failure result | Missing output or Build failure opens a bilingual reason surface with primary cause, failed step, affected output, and next action. |
| Selected inputs | Every selected CtrlRAM BIN, including optional slots, uses the completed green state without changing authoring authority. |
| IC/Number mismatch | Verified suggestions prompt before changing IC or Number. Accept retains compatible selections and reinspects once; cancel keeps context while authoritative Build still blocks contradictions. |
| Navigation | Leaving Merge/Replace with selected files prompts first. Confirm clears only that workflow's files/mapping-file selection; cancel clears nothing. |
| Action rail | Bottom-right actions are vertical; circular icons expand labels left on hover/focus without tooltip interception; Build stays the bottom primary action with keyboard, reduced-motion, and high-contrast behavior. |
| Layout | Base firmware and Common/topology sections align in width and use the reusable self-padding section control; Memory layout remains visible. |
