## Migration and evidence gates

Every production slice follows these rules:

1. Fix a baseline and characterize current behavior before moving ownership.
   Give every observed behavior exactly one disposition:
   `RequiredInvariant`, `KnownDefect`, `EvidenceRequired`, or
   `ApprovedChange`. Only `RequiredInvariant` is a pure parity blocker.
   `KnownDefect` requires a regression test for the corrected behavior and an
   explicit fix slice rather than preservation in the new owner.
   `EvidenceRequired` stays fail-closed and cannot authorize a firmware change.
   `ApprovedChange` records the accepted delta and tests the new contract.
2. Generate `SupportMatrix` from `CanonicalCapabilityCatalog`. During
   convergence enumerate the union of executable registries, UI-selectable
   catalogs, and publication/support catalogs; fail every unclassified
   divergence, keep every route, and do not downgrade its `DirectGolden`,
   `ApprovedAlias`, `SyntheticOracle`, `ContractOnly`, or `Missing`
   classification. Canonical authoring/publication policy must be explicit, and
   authoring, evidence, and publication decisions must pin the current stable
   `RouteId` plus `CapabilityFingerprint`. Missing/stale authoring is
   fail-closed; missing/stale publication/evidence cannot satisfy support or
   certification gates.
3. Record the real coverage baseline before applying a non-decreasing
   changed-module ratchet; a declared test count is not a coverage result.
   Separately report each slice's delta against the production-code measurement
   canonically defined by
   [`ADR 0021`](../adr/0021-code-size-ratchet-and-convergence.md). Each slice
   deletes superseded owners once caller and evidence gates permit and may not
   move equivalent logic into excluded paths or weaken any test/evidence gate.
   After the Workbench and legacy-runtime deletion milestones, a dedicated
   Canonical Core Convergence phase applies exact descending ratchets and
   reviewed candidate ledgers before final integration.
   The phase is one umbrella delivered through four ownership-bounded slices:
   Domain + Profiles, Application, Bootstrap + CLI, and Infrastructure +
   Contracts + CRC worker. Each slice supplies its caller inventory, deletion
   list, residual dispositions, architecture tests, and measured delta. New
   product features and UI layout changes are excluded, and shared
   registry/schema changes retain one writer.
   The former 18,000/12,000/7,500/5,500 slice targets and 44,000 total target
   remain dated planning benchmarks only. Each slice implements every
   compatible, evidence-backed, proportionate net-negative candidate and
   explicitly dispositions every residual item. Exact slice/total ratchets,
   slice-sum integrity, anti-relocation, and anti-gaming remain mandatory.
   Every Core Convergence PR reduces both its slice and total metric and creates
   no deletion debt. Before that phase, temporary growth is allowed only when a
   named R3 evidence gate or unmigrated caller prevents same-PR deletion. The
   existing issue/PR records old symbols, callers, added lines, exact blocker,
   deletion ticket, and latest milestone. Unclosed debt blocks the applicable
   #194/#195/#196 milestone; a TODO is not a deletion plan.
4. Move one responsibility through one compatibility seam.
5. Keep UI and CLI on the same Application contract.
6. Prove byte, report, selector/session, and accessibility parity appropriate
   to the slice.
7. Delete the old adapter only after every caller has moved. An R3 slice whose
   affected route still lacks its required direct or independent byte evidence
   may add the new seam and differential characterization, but may not delete
   the previous byte or processor owner.
8. Apply Polytail and independent review.
9. Keep R2/R3 architecture, firmware-owner, golden, and release gates intact.
10. Materialize the catalog at startup or through explicit Application
    `Reload Catalog` only. Validate a complete candidate before atomic
    publication; a failed reload retains last-known-good and a cold start
    without a valid snapshot disables every Build.
11. Preserve behavioral/golden evidence rather than implementation shape.
    Filename, type-name, partial-count, source-string, and source-position tests
    retire after equivalent behavioral/architecture coverage. Old/new
    differential tests name their deletion milestone and cannot keep an
    authority-zero production runtime alive; durable assertions become fixed
    golden, approved synthetic-oracle, or contract-sentinel evidence.
12. Assign every migrated invariant to exactly one runtime validator:
    Contracts shape, Domain firmware semantics, compiler selection/lowering,
    Application session/readiness, or processor-host mutation/tool checks.
    Remove downstream duplicate rules/messages/codes after typed boundary tests
    exist, and reject every path from a raw DTO directly to resolution or
    execution.
13. At Core Convergence entry, after Workbench/parallel-catalog and
    legacy-runtime deletion, freeze all four measured slice baselines and
    enable exact descending ratchets in the existing canonical verifier. Every
    Core PR lowers affected slices and total; cross-slice relocation is not
    reduction. Final integration enforces exact ratchets, slice-sum integrity,
    completed candidate ledgers, and existing release gates without another
    verifier or command.

M2 should favor behavioral/interface characterization over source-location
assertions. Existing source-string architecture tests remain until equivalent
coverage is demonstrably present; test-count or line-count reduction is not an
exit criterion.

## Design closure and downstream planning

The owner reopened and closed a focused convergence grill on 2026-07-28. Its
accepted decisions are normative as they are recorded here and in the canonical
ADRs and specification. The owner-design decision count for that original Core
program is **zero**. The owner approved the consolidated specification and `$to-tickets` synchronized
umbrella #229 plus slices #230-#233; separate implementation intake remains a
workflow gate rather than an unresolved design question. The previously
accepted firmware/domain ubiquitous-language register is accepted, including
DPCMI-derived DP Version,
DP/Initial Code/LDC, Standard/AB Merge, IC Count, FirmwareConfig General
Parameters, FlashCode, and AB artifact/bank terminology plus each legacy
alias's migration disposition. Stable `RouteId`, firmware-semantic
`CapabilityFingerprint`, per-publication `ResolutionToken`,
`AuthoringRevision`, and `FileStamp` have distinct accepted meanings.
`FileStamp` is the selected file's accepted byte length plus SHA-256; path and
filesystem timestamp are non-authoritative hints, and it is not a
firmware-semantic fingerprint.
Authoring, evidence, and publication decisions pin route plus fingerprint and
never inherit across changed semantics. The typed-ID/hash-closed trusted bundle
representation, separate package trust index, bundle-scoped version model,
current-schema-only runtime, explicit offline migration path, data-only
existing-vocabulary IC onboarding, and no-executable-plugin rule are accepted.
The resolved-capability child
boundaries, reference-only metadata/composition plans, artifact/session split,
and child-local readiness model are accepted. The Hex Viewport seam and owner,
slot status lifecycle, and
disclosure are accepted; its remaining metadata fact-grid layout is consolidated
with the shared Information Card question. Report one-line summaries, shared
button interaction states, the memory-layout visual grammar, CtrlRAM subtype
presentation, and the responsive Information Card/fact-grid anatomy are also
accepted directions. The fixed six-mode,
metadata-only in-memory authoring-session lifetime, stale-result publication
gate, and separation from current inspection bytes, report history, and Hex
Editor memory are accepted. General Merge/Replace mapping authoring now also
has one accepted typed draft, range codec, Start + Length editor, and
UI/CLI/Saved Rule round-trip contract. Shared
`AuthoringAvailability`, compiler-proved `ExecutionAdmission`,
`EvidenceStatus`, `PublicationStatus`, `InputReadiness`, and refreshable
`RuntimeDependencyReadiness` are separate dimensions. Build derives only from
authoring, execution, input, and runtime dependency readiness; a valid
`EvidenceStatus.Missing` blocks certification/release rather than byte
execution. Output
naming is accepted as a compiled capability over the canonical inspection
snapshot, using the normal
`{IC}_{OutputType}_{VersionInfo}_{Date}.bin` skeleton and separate host-owned
destination/commit policy. The existing overall palette, explicit light-theme
role/subtype anchors, `MemoryContentRole` primary-fill rule, and separate
workflow/diagnostic/interaction effects are accepted.

The first canonical tracer is exactly NT51929 Standard Merge with a `0x40000`
map, DP `[0x0000,0x6000)`, explicit gap `[0x6000,0x7000)`, TP
`[0x7000,0x40000)`, two copy operations, and no processor. Application owns the
IC-neutral catalog/query/command seam; CLI and the temporary Workbench adapter
share it. Catalog refresh is explicit and atomic. The Message Center shares
only a shell entry/visual container between immutable Run Reports and
refreshable System Information; system transitions are bounded/in-memory and
diagnostic export is versioned/privacy-filtered rather than Report History.
