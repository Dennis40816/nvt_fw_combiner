## Universal special-value BIN validation

A universal validation BIN can reduce owner effort before real golden outputs exist. It does not replace golden parity, but it catches mapping mistakes quickly.

Recommended pattern:

1. Use a base firmware whose target regions are not already the same repeated byte.
2. Generate one replacement BIN per slot with a deterministic sentinel pattern:
   - `normal`: seed `0xA1`
   - `mp`: seed `0xB2`
   - `diff/dlm`: seed `0xC3`
   - `vn`: seed `0xD4`
   - `nf`: seed `0xE5`
3. Within each BIN, encode offset as `byte = (seed + offset) & 0xFF`; this proves both start address and length.
4. Run Replace + required postbuild.
5. Verify that every selected declared region contains the matching sentinel/address pattern, except bytes explicitly owned by postbuild CRC/header/header-copy writes.
6. Verify that unselected regions match base, except declared postbuild writes.
7. For truncation policy, add one oversized file per CtrlRAM slot and assert the report contains the truncation warning and the output uses only the declared region length.

This universal case is useful for:

- confirming slot-to-address wiring;
- finding swapped `Normal/MP/VN/NF/DiffDLM` inputs;
- confirming `single/cascade/2/3` visibility;
- validating General Replace explicit mapping bounds.

It cannot prove:

- exact legacy combiner parity;
- customer real-output CRC correctness;
- overlay/map.txt behavior;
- NT51931 production mode selection.
