## General Merge large-file review — 2026-09-23

固定來源：`39e934b514928782581d7c27a5cfd8feaad484fa`。範圍是 Customized／General
Merge 的 desktop、Application／shared execution 與 delivery 路徑；CLI／Saved Rule
共用 owner 列入修改影響。Luna max 唯讀檢查 input／UI，root 檢查 compiler、executor、
output／report 並整合。方法為 CodeGraph、限定 source／ADR／test assertions 閱讀；
沒有新測試、效能量測或原客訴的實檔重現。

**Findings（相對於本次新需求）：** 現有 2 GiB 級上限屬既有契約，不能當作偶發回歸；
但目前架構無法達成大檔不限於整檔記憶體配置的需求。Polytail verdict：**FAIL**。

Input lifecycle 的 canonical authority 仍是 [ADR 0044](../adr/0044-content-authoritative-general-selected-files.md)：
[ADR 0048](../adr/0048-headless-slot-readiness-and-compilation-identity.md) 與
[ADR 0049](../adr/0049-unified-preload-lifecycle.md) 明確保留 General reopen 契約。
限定搜尋後續 ADR／contracts 未找到允許 General authoring 保存整檔的替代決策；
上述 payload retention 屬 code／test 與契約 drift，不能以 passing test 取代 authority。

**建議實作順序（尚未實作／准入）：**

1. 先閉合 General input lifecycle 契約，讓檔案選取僅持有長度、完整 SHA 與 revision，
   並以 bounded memory 完成完整檔案 hash。保留 cancellation、short-read／growth probe、
   stale lease 及明示 Reload；不能用 timestamp 或只 hash mapped slice 代替完整 identity。
   共用 inspector 的 BuiltInFirmwareInspection／Replace consumers 仍需 bytes，不能全域改空。
2. 從「大來源只取小 slice」打通到 Preview／Build：每次 run 重新驗證來源並建立受控
   immutable disk snapshot，驗證成功後供相同 plan 使用。可在單次 run 內共用同一來源，
   不能僅依 path 跨 revision 重用，也不能繞過 accepted-stamp mismatch。
3. 再讓同一 executor、mutation evidence、output artifact、loose／bundle delivery 支援
   大 output；以 checked `long` 保持範圍，消除大 offset 的 `int` casts。保留原子提交、
   cancellation／failure cleanup 及來源不可變，磁碟不足等實際限制回傳明確錯誤。
4. 各階段同步 ADR 0019／0047、profile／schema／trusted resource envelope 和 consumer tests；
   既有 4096 mapping 數量、overlap、inline budget 等規則不是本需求的移除對象。
   獨立 Hex Editor 的 8 MiB 編輯契約也不阻擋 General Browse；若要編輯大檔需另設
   lazy/random-access 模式，不以提高 Hex 上限代替本修正。

**所需證據：** 超過 2 GiB 的 source 僅取小 slice、source offset 跨 2／4 GiB、跨 chunk
讀寫；大 output 的 gap／fill／完整 hash；同尺寸替換、讀取中增減、Preview→Build
來源變更與 stale lease；多 mapping 同來源、bundle 完整 source 與 loose parity；
取消、disk-full、permission failure 與 atomic cleanup；交錯 byte diff 的 bounded-memory。
虛擬 range source 可覆蓋大 offset 算術，仍需受控真實 file integration 與 memory evidence。
共用 engine 改動還需既有 Standard／AB／Replace 回歸及適用的發布 Golden。

現有 [inspector tests](../../tests/NvtFwCombiner.Infrastructure.Tests/Files/FileContentSnapshotInspectorTests.cs)
有小檔 hash、short-read／growth／cancel 等案例；[logical compiler tests](../../tests/NvtFwCombiner.ProfileContract.Tests/TrustedProfileBundleCatalogFactoryTests.LogicalOutputV25.cs)
lines 114–138 刻意驗證超過 `int.MaxValue` 的來源被拒絕，即使 mapping 只有 2 bytes。
[General lifecycle tests](../../tests/NvtFwCombiner.Bootstrap.Tests/GeneralSelectedFileExecutionLifecycleTests.cs)
line 59 的 `GeneralMergeBuildReusesAcceptedBytesAfterSelectedPathChanges` 鎖定 captured payload
重用，需與 input lifecycle authority 一同處理，不能只刪除失敗測試取得通過。
沒有現成大檔成功／記憶體上界證據，本次不宣稱已解除限制或通過 regression。

## Launcher 更新計畫的交接

詳細設計沿用 [Launcher 差異更新、自更新與內網遷移提案](launcher-update-proposal-20260923.md)，
不複製成第二份規格。`1.2.1` 啟動開發及相容性／故障驗證，完整 Launcher 正式發布目標
仍為 `2.0.0`；不能把排程調整解讀成下次 release 啟用 Launcher。

1. 先量測相鄰真實 release ZIP 的 chunk 重用、Check／metadata／fallback 總流量，
   找出目前 Check 先讀完整 package 對差異傳輸收益的影響。
2. 第一個端到端單元復用既有來源，以差異 chunks 重組完全相同 ZIP，再進入既有
   verifier／materializer／READY／rollback；保留完整下載 fallback，沒有第二套 installer。
3. Launcher 自更新延伸 ADR 0056 的 Bootstrap／版本內 Launcher 與精確回復，
   測試 App 與 Launcher 更新中斷、重啟、READY timeout、失敗回復及並行實例。
4. source locator 與 publisher identity 分離，讓 file／UNC／HTTPS 共用 typed transport；
   依第一個實際內網的認證環境驗收，新 client 換來源不應要求修改核心程式。
5. 同步 publisher、cache／resume、信任驗證及相容矩陣。舊 client 可能需要一次 bridge，
   不承諾所有歷史版本只换 URL 就可無人操作移轉。

實作前仍需 owner 決定：首版是否需要獨立 Launcher-only hotfix、首套內網 transport／
認證方式，以及是否接受一次受控 bridge。先完成不依賴這些答案的樣本量測與既有 owner
確認，不為等待決策而重跑已完成的 source inventory。

原 35–60 人日是整套方案的未校準粗估，10–18 日為包含在總量內的初段估算；
都不是 Codex 實際等待時間或交期承諾。用上述端到端結果重估後續範圍。
