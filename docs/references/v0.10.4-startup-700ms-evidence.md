# v0.10.4 Home startup 700 ms evidence

Status: candidate evidence. A predecessor working-diff package met the local
700 ms median gate. The current continuous-progress/focus delta is not yet
measured and is not release authority: owner review, the canonical frozen-diff
verifier, and an exact-package measurement remain required before release.

## Contract

The controlled package gate uses the repository's
`scripts/measure-startup.ps1` runner and the exact compressed single-file,
self-contained `win-x64` publish shape. One launch warms the OS/runtime path but
is not scored. The following five Home launches are measured from external
process creation to a nonzero main-window handle. Their median must be at or
below 700 ms. The unscored cold launch is retained as a separate observation;
this local gate is not a universal CI timing threshold.

Publish flags are `PublishSingleFile=true`,
`EnableCompressionInSingleFile=true`, `PublishReadyToRun=true`,
`PublishReadyToRunComposite=true`, `PublishTrimmed=false`,
`IncludeNativeLibrariesForSelfExtract=true`, and self-contained `win-x64`.

## Root cause and correction

The first Home shell constructed `WorkflowSessionPresentationViewModel`, which
immediately requested AB profile summaries, all IC ids, and the default IC.
Those read-only Presentation queries called the lazy canonical catalog's first
publication synchronously. A diagnostic release build localized that one call
to about 3.2 seconds and about 0.9 GB of allocation before the first window.

The correction restores the already-specified startup lifecycle:

1. shell construction creates Home without reading the catalog publication;
2. Home workflow commands remain disabled while the canonical publication is
   unavailable;
3. the post-open worker consumes `ICanonicalCapabilityCatalogLoader.LoadAsync`;
4. the UI-thread continuation applies the exact canonical IC, default IC,
   and AB-profile choices once; and
5. only then are the six Home workflow-entry commands and the Merge/Replace
   navigation commands enabled, the requested catalog-backed launch page is
   applied, and catalog-backed workflow localization/materialization is
   allowed.

If canonical publication fails, those entry points remain disabled and the
failure is traced; Presentation does not substitute inferred or stale support.
The visible Home window is covered by the reusable foreground loading surface
while publication is pending, so pointer/keyboard selection cannot race the
catalog. The measured candidate's startup coordinator reports only observable
lifecycle milestones: foreground preparation (`0%`), catalog work starting
(`10%`), background catalog warm complete (`80%`), UI publication starting
(`90%`), and UI publication complete (`100%`). The surface shows those exact
milestones beside the Preparing title; it does not estimate elapsed time,
bytes, or external-processor work. Failure keeps the blocking surface visible with an
explicit localized retry action. Retry uses the existing explicit catalog
reload contract rather than replaying a cached cold-start failure. The
percentage is included in the polite accessible status. Reduced-motion mode
keeps the same determinate value without decorative animation.

The current unmeasured working candidate replaces the `10%` through `80%` gap.
Each startup or Retry attempt starts one exact catalog reload and receives only
that operation's read-only progress stream. The source reports FIFO completion
for every real canonical route and closes the stream on every exit; Presentation
drains it before advancing to the truthful `80%` route-ready milestone. Caller
code cannot inject a writer or callback under the catalog publication lock, no
timer estimates work, and cached or unrelated reloads cannot capture the stream.
The original continuous activity bar remains animated while loading; adjacent
text advances through `10%`, `20%`, ..., `80%` when actual route completion
crosses each threshold. The existing localized detail continues to identify the
canonical catalog work. The package hashes and controlled measurements above
do not cover this delta; an exact-package rerun is a mandatory residual gate.

The final startup reduction does not postpone or discard user preferences. The
same 64 KiB-bounded, best-effort preference reader begins before host-graph and
Avalonia initialization, then its immutable snapshot is obtained before the
main window is constructed. Language, theme, and reduced-motion state therefore
remain correct on the first visible frame without a default-theme flash. Invalid,
missing, inaccessible, or oversized documents retain the same fail-closed
defaults; no second preference store or execution path was introduced.

No IC is hard-coded, no second catalog/cache is introduced, and Presentation
does not infer support. The broader observable, cancellable, bounded, and
user-controllable preload lifecycle remains `v0.10.5` scope.
