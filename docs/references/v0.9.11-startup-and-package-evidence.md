# v0.9.11 startup and Windows package evidence

## Scope and result

This record compares the exact annotated `v0.9.10` release tag with the
commit-pinned `v0.9.11` development candidate after startup projection deferral
and self-contained single-file compression. It is local Windows evidence, not a
universal wall-clock guarantee.

The owner targets were a first window within 0.8 seconds and a main executable
no larger than 70,000,000 bytes. The executable target is met. The startup
target is not: the measured median improves from 2,922.5 ms to 2,103.6 ms, but
the remaining self-contained .NET/Avalonia launch cost is still above 0.8
seconds.

## Environment and protocol

- Windows 11 Enterprise `10.0.26200`, Intel Core i9-10900F, 20 logical
  processors;
- .NET SDK `10.0.302` and PowerShell `7.5.8`;
- official package output from each named commit, not a framework-dependent or
  loose-DLL development build;
- one warm-up followed by five launches on the same machine;
- elapsed time begins immediately before `Start-Process` and ends when the
  process exposes a nonzero `MainWindowHandle`;
- every measured process exposed a window and did not exit early; each process
  was closed before the next run.

This protocol includes process, self-contained host, single-file, managed
runtime, Avalonia, composition-root, ViewModel, and first-window construction.
It is sensitive to machine and OS cache state and therefore supports only the
same-machine before/after observation below.

The repository now provides the repeatable
[v0.9.11 startup measurement tool](v0.9.11-startup-measurement-tool.md), which
correlates process-to-window observations with opt-in Avalonia/application
milestones and preserves every raw sample in one JSON result.

## Attribution and retained boundaries

The candidate unpacked package contains 51,152,906 bytes for the main
application, 13,135,047 bytes of approved reference evidence, 8,469,069 bytes
of approved external tools, 3,105,614 bytes of built-in profiles/runtime
catalogs, and 128,338 bytes of manifest, hash list, notices, license, and
README. Only the main executable uses .NET single-file compression. Nothing was
removed from the closed profile, reference, external-tool, localization, font,
accessibility, SBOM, or provenance surfaces.

Startup improvement comes from keeping Settings summaries, workflow slots,
number choices, General Merge length, and memory projections out of initial
shell construction until their page or API path requires them. Typed profile
validation remains fail closed at first use. Standard Merge single-IC lookup no
longer materializes all selectable IC summaries.

`PublishTrimmed` remains `false`; the package remains self-contained `win-x64`
and includes native libraries in the single-file bundle. NativeAOT was rejected
after the reflection-based JSON catalog loader produced `IL2026` and `IL3050`
and a further exploratory publish produced no executable. A no-restore
ReadyToRun probe failed safely with `NETSDK1094` because no valid R2R runtime
pack was present. Neither path was added to the release dependency or restore
surface.

## Gates

Release smoke now rejects `NvtFwCombiner.exe` above the owner's
70,000,000-byte maximum in addition to the existing 58,076,715-byte ZIP budget.
The measured 0.8-second startup target remains unmet and must not be presented
as complete. Final release still requires independent R2 startup architecture
review, R3 package/release review, and clean Windows x64 verification without a
preinstalled .NET or Python runtime.
