# v0.9.11.5 startup delay-loading evidence

## Scope

`0.9.11.5` is the owner-selected integration branch name, not a four-part
release version. The packaged probe keeps assembly version `0.9.11`; `VERSION`
is unchanged. This slice changes Presentation startup only. It does not change
composition requests, profile selection, firmware ranges, processors, output
bytes, reports, or runtime dependencies.

The implementation is split into three reviewable commits:

- `c12aeeec` reuses the immutable English and Traditional Chinese shell text
  bundles instead of rebuilding the complete resource object for each shell
  projection;
- `e3b289c0` defers the raw Hex Editor workspace and initial General
  Merge/Replace mapping rows until their first owning workflow is used;
- `34f07b19` keeps inactive page and modal visual trees unmaterialized on Home,
  then creates each tree once on first use and retains it across later page
  switches so local focus/scroll state is not repeatedly discarded.

## Comparable packaged Home result

Both retained probes use self-contained compressed single-file `win-x64`,
trimming disabled, native libraries inside the bundle, one warm-up, and five
measured Home launches. These are same-machine observations, not universal CI
thresholds.

| Probe | Process to window samples (ms) | Median | Managed entry to opened |
| --- | --- | ---: | ---: |
| Before `31e08f06` | 2064.768, 2032.706, 2036.853, 2030.859, 2014.124 | 2032.706 ms | 1974.897 ms |

The two equivalent final-code observations put the current normal-package Home
startup at approximately 1.12-1.25 seconds on this machine, a 39-45% reduction
from the 2.03-second predecessor. The spread also demonstrates why this result
must not be represented as a universal one-second guarantee.

The dominant app-controlled blocks changed as intended. Shell ViewModel
construction fell from a 771.030 ms median to 35-40 ms. The post-ViewModel
constructor/binding block, which was 740.210 ms in the intermediate lazy-state
probe because hidden views still materialized, fell to 20-23 ms after the
visual-tree split. MainWindow XAML fell from 291.050 ms to approximately
146-163 ms. The remaining major intervals are Avalonia/runtime initialization
and the platform window-open transition rather than eager workflow projection.

## First-use and rollback evidence

The launch-option harness successfully materialized Settings, Merge, Replace,
and Hex Editor from an initially empty visual host. One cold diagnostic sample
was 3849.031 ms, 2203.870 ms, 2159.041 ms, and 1330.497 ms respectively. These
single samples prove the paths construct and open; they are not performance
claims. Settings and workflow first-use cost remains a follow-up optimization
candidate, but it no longer blocks Home's first paint.

Page and modal hosts remain null until their owning state is first visible.
After creation, content is retained and visibility alone controls later page
switches. The existing ViewModels, commands, bindings, Build handlers, modal
actions, and Hex Editor state continue to own behavior. The change can be
rolled back independently by reverting `34f07b19` without changing firmware
semantics.

## ReadyToRun experiment rejected

A composite ReadyToRun probe reached a 664.023 ms Home median and a 412.420 ms
managed-entry-to-opened median. Its executable was 69,956,989 bytes, within the
70,000,000-byte executable target. It is not adopted:

- zipping that executable alone produced 64,254,473 bytes, already above the
  complete release-package ceiling of 58,076,715 bytes;
- the current complete package baseline is 56,782,109 bytes before that growth;
- a clean non-composite ReadyToRun probe failed closed during startup with
  Windows process exit code `0xC0000602`.

The composite result proves that sub-0.8-second startup is technically possible
on the measured machine, but it cannot enter the release path while the closed
package-size and clean-start gates remain unsatisfied. No ReadyToRun property,
package rule, dependency, or size ratchet is changed by this slice.

## Residual repository gate

The canonical verifier remains blocked before affected tests by the pre-existing
private owner-handoff file
`testdata/golden/owner-handoff/combiner-and-51929/intake/929_golden_combiner_source_code.7z`:

stage, or otherwise weaken that evidence gate.
