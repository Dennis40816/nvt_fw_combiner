Status: owner-approved direction inventory as of 2026-08-11. Each cross-layer
item still requires its bounded R2 contract, tests, review, and milestone gate;
the approval does not move unified preload control out of `v0.10.5`.
Audit date: 2026-08-11.
Audited base: `848308e8562b1364f884ec6c9ffa3312d4115489` plus the current
`v0.10.4` startup/loading/theme working tree.

Follow-up on 2026-08-13: `v0.10.4` completed the Report resource half of the

`ReportModal`; `MainWindow` merges only its shared/page/workflow/shell resources.

caller evidence.

## Scope and method

The audit covered every counted production slice and the Presentation source:
Domain, Profiles, Application, Infrastructure, Contracts, Bootstrap, CLI,
Desktop, the CRC worker, C# Presentation code, and AXAML resources. The review
used the repository CodeGraph/caller inventory, physical-source measurement
from `scripts/code_size_policy.py`, the largest partial-type inventory,
project-reference and direct-caller searches, existing architecture/retirement
evidence, and actual Light/Dark desktop screens.

The audit does not treat a large file as duplication by itself. A candidate is
listed only when there is a concrete repeated transformation, eager operation,
or misplaced platform responsibility. Firmware semantics, diagnostics,
fingerprints, exact ranges, report wire compatibility, and golden behavior are
not candidates for deletion merely to reduce line count.

## Recommended architecture opportunities

| Priority | Observed evidence | Recommended direction | Expected payoff and gate |
| --- | --- | --- | --- |
| 1 | A live run is serialized in `CompositionRunPresentationViewModel` and immediately parsed again by `ReportReviewViewModel.Factory`. | Project an in-process typed `CompositionRunReport` directly to the review model. Serialize once, asynchronously, only for persistence/export/history; retain the external JSON-load route. | Removes a complete JSON round trip and its allocation/latency. R2 Application/Presentation contract change; exact report JSON, history, cancellation, and large-report evidence must remain unchanged. An honest LOC reduction is not known until the typed projector spike is measured. |
| 1 | `BuiltInFirmwareInspection.InspectFirmwareBatch` calls DP, Standard, CtrlRAM, and AB authoring inspectors for every batch even though each `FirmwareInspectionSnapshotInput` declares which workflow roles are present. | Dispatch only the required inspection strategies while keeping one distinct-path read cache and the same result merge/order. | Avoids irrelevant compiler/catalog/readiness work during selection. R2 Infrastructure/Application change; differential status, diagnostic ordering, read-count, and all existing golden behavior must pass. |
| 1 | `FirmwareInspectionSession` and `FirmwareFileIdentity` perform before/after filesystem identity capture and retain path caches in Presentation while Infrastructure performs the actual reads. | Return a coherent inspected-content identity and stability result from the filesystem adapter so Presentation only owns generation, selection, and display caches. | Clarifies the platform boundary and removes UI filesystem probing/common-mode races. R2 because stale-file rejection and Build reinspection are safety behavior; likely modest net code reduction. |
| 1 (`v0.10.5`) | `MainWindow` eagerly merges seven report dictionaries totaling 911 nonblank AXAML lines before the first window. Startup also has separate flags/cancellation for catalog and deferred page warm-up. | Make the Report experience own and lazily load its resources, then place catalog/page/report preloads behind the already-planned single observable, cancellable, bounded coordinator. Reuse `ForegroundLoadingState` as presentation state rather than inventing another progress model. | Reduces first-frame XAML parse/materialization and makes loading behavior consistent. Mainly a measured startup/allocation win; resource extraction alone is not a LOC-reduction claim. Must preserve the 700 ms package gate and allow selection only after canonical publication. |
| 2 | CLI source aliases and calls Infrastructure `ProtectedPathGuard` directly while the output destination adapter independently enforces protected-path rules. | Define one typed Application admission/result for output and report targets; keep client-only parsing and exact CLI diagnostics at the CLI edge. | Removes layer coupling and duplicate alias orchestration. R2 security/path change; Windows path equivalence, input/output/report collision, atomic publication, and exact messages require focused evidence. |
| 2 | Bootstrap `ExternalProcessorFactory` discovers directories, parses `manifest.json`, validates every scalar/array, creates processors, and manages lifetime. | Move filesystem discovery and strict manifest materialization behind an Infrastructure environment factory; leave Bootstrap with composition and lifetime wiring only. | Restores the declared Bootstrap boundary. Likely a small net reduction, not hundreds of lines, if existing strict JSON/schema helpers can be reused without changing diagnostics or package trust. |
| 2 | `ShellTextResources` contains 1,950 nonblank C# lines across 12 partials for static English/Traditional Chinese labels plus dynamic formatters. | Generate or load strongly typed static resources and retain only typed dynamic formatting logic in C#. | Improves translation completeness and reviewability. This is maintainability work, not a valid source-size reduction unless generated output remains measured and reviewed. |
| 2 (UI) | Hex history feedback owns an 18-frame/35 ms timer and custom color interpolation, while the viewport font is a hard-coded `Cascadia Mono, Consolas` family. | Bind feedback motion to the existing reduced-motion preference and resolve the monospace family from a theme resource. | Fixes accessibility/theme consistency with a small local change. No meaningful LOC saving is expected. |

## Deliberate non-candidates

- `V2CompositionPlanCompiler` (2,798 nonblank), `CompositionRunService`
  (2,165), the family/profile normalizers, compiled composition, and
  fingerprint writers remain canonical safety owners. Their size alone does
  not justify a split or deletion.
- Firmware validations that appear after earlier validation are retained when
  they protect a different trust boundary or reject detached but value-equal
  objects. Fingerprint or golden equality cannot replace reference/authority
  admission.
- Moving code from a counted layer to Presentation, tests, scripts, generated
  files, or documentation is not a reduction.
- The required Legacy Combiner process adapter, staged-copy diff enforcement,
  and worker protocol are product behavior, not legacy architecture.

## Recommended sequence

1. Complete and verify the current foreground loading and theme correction;
   keep its exact +786 full-production cost visible.
2. Treat the typed live-report path and workflow-selective inspection as the
   first two bounded performance/architecture spikes. Measure allocation,
   latency, gross/add/net source, and exact behavior before accepting either.
3. Execute lazy report resources and the unified preload coordinator together
   under `v0.10.5`; separately changing each page's loading lifecycle would
   create another transition layer.
4. Schedule filesystem identity/path admission and external-tool discovery as
   independent R2 boundary tickets. Do not mix them with firmware changes.
5. Hex reduced-motion/font work is complete in the `v0.10.4` UI/theme PR.
   Handle localization generation as an independent reviewable change.

The reasonable conclusion is not that the codebase is mathematically optimal.
It is that the large legacy deletion is complete, and the remaining credible
work is targeted boundary and performance convergence. None of the observed
items supports another multi-thousand-line deletion without removing retained
product behavior or merely relocating code.
