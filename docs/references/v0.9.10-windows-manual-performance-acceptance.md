## Safety setup

1. Use disposable copies of approved inputs for unavailable-path scenarios.
   Never rename, delete, lock, or disconnect the only copy of an owner artifact.
2. Record the current Windows contrast theme before changing it. Restore the
   original theme after the rendered visual check.
3. Use the same machine, power mode, package, inputs, and warm-up policy when
   comparing Node B and Node C. Record raw observations; do not invent a pass
   threshold after seeing the result.
4. Keep Task Manager, Performance Recorder, screen capture, and assistive
   technology outside the timed interval unless both nodes use the same setup.

## A. Cold first frame and Build entry

1. Start the reviewed desktop package from a cold process.
2. Open Merge, then Replace, without selecting a BIN.
3. Record process-start-to-first-interactive-frame and page-switch latency.
4. Select the approved large local test copy and immediately interact with
   navigation, scrolling, and the other file picker.
5. Start Preview or Build once all required inputs are ready.
6. Prepare a separate cold-start session whose local history reaches the
   maximum retained state allowed by both the 12-entry and 16 MiB soft limits,
   including one non-confidential 10,000-range performance report. Use 12
   entries only when their total retained payload stays inside the byte budget.
   Restart the exact package and interact with page navigation while history
   restoration is pending.
7. Prepare another cold-start session with an approved non-confidential large
   report copy passed through `--load-report` using its runtime-resolved path,
   together with `--open-report`. Interact with navigation while the source is
   read and projected; do not record or commit the physical path.
8. In a separate session, switch theme, language, and reduced motion several
   times while continuing to navigate. Close normally, restart the same
   package, and verify the final complete preference snapshot is restored.
   Repeat once with Traditional Chinese as the persisted startup language and
   confirm the first interactive shell does not transiently publish English
   content before rebuilding the same page.
9. Open the Raw Hex Editor with an approved non-confidential 8 MiB test copy.
   Record load completion and process working set, navigate to the final page,
   and apply one overwrite. Confirm that an insert at the exact 8 MiB limit
   fails without mutation. Delete one disposable tail byte, insert one byte to
   restore the exact length, then undo and redo all three successful operations.
   Finally run repeated ASCII Search/Next while continuing to resize or navigate
   the shell.

Pass conditions:

- the first window and page navigation remain interactive without a visible
  dispatcher freeze;
- selection publishes the loading state before inspection completes;
- Build/Preview publishes active progress before composition/report work;
- the progress panel remains visible across navigation and reaches the final
  typed phase without duplicate execution;
- report projection opens only after complete state is available; no partial
  report/history entry appears;
- the bounded-history cold start remains interactive, restores at most 12
  entries within the 16 MiB soft budget, and publishes only the newest complete
  review;
- the explicit startup report opens only after complete projection and cannot
  overwrite a newer report created while its source is still pending;
- rapid preference changes do not freeze navigation, normal close remains
  bounded, and restart restores the final theme/language/reduced-motion values
  rather than a superseded intermediate snapshot; and
- the 8 MiB Raw Hex Editor session remains interactive, retains exact
  source/current/structural byte cues through undo/redo, and repeated search
  does not cause another document-sized working-set jump per invocation.

Record first-frame, page-switch, loading-state, first-progress-step, and
first-report-page observations in the result table below. Record the two
startup-report sessions separately from the empty-history cold start.

## B. Slow, superseded, and unavailable inspection

Use an owner-approved disposable BIN copy on a known slow removable or network
location for the slow-path check. Use two distinguishable approved copies A and
B for latest-wins. Use another disposable copy U for the unavailable check.

1. Select A. While its inspection is visibly loading, select B in the same
   slot.
2. Confirm the shell remains interactive and the loading state belongs to the
   latest selection.
3. After both reads settle, verify only B's path, version tokens, firmware
   facts, IC hint, Number/context suggestion, memory display, and output-name
   projection are visible. A must not publish a late notification.
4. Select U, then make only the disposable test copy unavailable using the
   reviewed local test procedure. Do not alter an owner source artifact.
5. Confirm the shell does not crash, loading clears, incomplete facts remain
   absent/unknown, and a subsequent Build performs its authoritative reread.
6. If Build is attempted with U unavailable, it must fail without committing an
   output and must expose the Application report/error evidence.

The inspection snapshot is display-only. Passing this scenario must not be
interpreted as permission to cache away Build-time file reads or weaken
Application validation.

## C. Narrator or NVDA announcements

Use Narrator or NVDA for each separate subscenario below. Record the approved
case id, byte length, and SHA-256 for every input; resolve its physical path at
execution time.

1. Repeat the slow A-to-B latest-wins scenario from section B.
2. Select an approved base whose verified IC/context hint opens the mismatch
   confirmation, accept it, and wait for the successor inspection to settle.
3. In CtrlRAM Replace, use an approved IC transition whose target context has
   the same safe replacement slot. Accept the hint and confirm the populated
   replacement remains selected and is reinspected.
4. In a separate CtrlRAM Replace session, use an approved IC transition whose
   target context lacks that safe replacement slot. Accept the hint and confirm
   the populated replacement is dropped with its reason.
5. Start one verified Preview or Build and observe the typed progress phases.

Pass conditions:

- the localized inspection loading/readiness status is announced once per
  meaningful latest-generation transition;
- a stale inspection completion is not announced;
- accepting the base IC/context hint announces the resulting context update;
- the compatible replacement-retention scenario announces the retained
  context without a stale or contradictory drop message;
- the unavailable-slot scenario announces that the replacement was dropped
  and gives the bilingual reason; and
- typed run progress announces the parent phase/state once without repeating
  its visual-only glyph.

Record the exact unexpected duplicate, missing, or stale utterance as a failure;
do not replace an assistive-technology session with a XAML source assertion.

## D. Rendered Windows contrast-theme Hex Diff

Use a verified in-session Replace result containing accepted and
review-required changes. Open Changes, select a range, and enable original rows
before switching Windows to the reviewed contrast theme.

Pass conditions:

- Changed, Original, Selected, accepted, and review-required meanings remain
  readable without relying on green, blue, or warning color;
- the selected navigator row retains a visible outline and keyboard focus;
- output and original hex/ASCII rows remain distinguishable at the recorded
  display scale;
- right-side reason, verdict, evidence, hashes, and half-open address range
  remain readable;
- keyboard range selection, address jump, paging, splitter resizing, and the
  original-row toggle remain operable; and
- focus, text, and controls are not obscured, clipped, or rendered with
  insufficient effective-theme contrast.

Capture a redacted screenshot only when repository policy permits it. Restore
the original Windows contrast theme when finished. A source-token or binding
test is not rendered high-contrast evidence.
